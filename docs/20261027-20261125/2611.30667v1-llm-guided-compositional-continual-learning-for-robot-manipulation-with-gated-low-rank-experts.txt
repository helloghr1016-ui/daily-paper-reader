LLM-Guided Compositional Continual Learning for Robot Manipulation
with Gated Low-Rank Experts
Nilay Kushawaha*1, Abdalla Swikir2, and Fares Abu-Dakka1
Abstract— General-purpose manipulation robots must ac-
quire new skills over time without forgetting prior ones or
retraining from scratch. We present a continual learning
framework that represents each skill as a dedicated expert sub-
network in a Progressive Neural Network (PNN). New tasks
reuse prior knowledge through low-rank adaptation (LoRA)
modules on lateral connections controlled by learnable per-
parent gates, enabling explicit attenuation of individual transfer
paths while reducing the parameter cost of dense PNN laterals.
For long-horizon deployment, a frozen local large language
model decomposes natural-language instructions into sub-tasks,
routes them to suitable experts, and requests a new expert only
when the library is insufficient. Using a shared task-space action
interface, we evaluate the framework on twelve MetaWorld
tasks and in a Sawyer-to-Panda-to-UR5e cross-embodiment
transfer experiment, showing improved task success relative
to learning from scratch when demonstrations are limited.
Real-robot manipulation experiments further demonstrate that
the proposed framework supports compositional execution and
expert orchestration.
I. INTRODUCTION
Robots operating in unstructured environments must ac-
quire new manipulation skills throughout their lifetime with-
out losing previously learned ones. This requirement is
difficult to satisfy with the dominant paradigm of training
a single monolithic policy across all tasks. When new tasks
are added, previously acquired knowledge can be partially or
completely overwritten, leading to catastrophic forgetting [1].
Continual learning (CL) addresses this problem by enabling
incremental skill acquisition while preserving earlier capa-
bilities. However, forgetting is not the only limitation of
monolithic policies [2]. Because different skills are entangled
within the same set of parameters, it is difficult to identify
which part of the network is responsible for a particu-
lar behavior or to quantify how much a new skill reuses
prior knowledge. In safety-critical robotics [3], this lack
of transparency limits inspection, verification, and selective
deployment of individual competencies.
We address these issues by learning each skill as a ded-
icated expert that is preserved after training and composed
only when needed, as shown in Fig. 1. Our architecture is
based on a Progressive Neural Network (PNN) [4], where
every task is assigned a new column, or sub-network, that is
frozen once learned. This prevents parameter overwriting in
previously learned columns. To enable forward knowledge
transfer with a lower per-connection parameter cost than
dense lateral connections, prior knowledge is reused through

the symbolic planning level and is never fine-tuned, keeping
task reasoning separate from low-level control and making
the high-level task decomposition and routing explicit.
Using shared task-space action conventions, we also evalu-
ate the gated transfer mechanism across robot embodiments.

Panda and UR5e arms in Robosuite [8], and finally to a
real Franka Research 3 (FR3) arm performing a long-horizon
manipulation task. In the simulated cross-embodiment exper-

than learning from scratch at every tested demonstration

as follows:

II. RELATED WORK
A. Continual Learning for Robot Manipulation
CL methods are commonly grouped into three categories:
Regularization methods preserve previous knowledge by
penalizing changes to parameters that are important for past
tasks [1]. Rehearsal methods revisit stored samples from
earlier tasks, or generate synthetic ones, to reduce forget-
ting [9]. Architectural methods allocate separate capacity
to new tasks, either by expanding the network with task-
specific modules [4], [10] or by partitioning a fixed-size
model through pruning or masking [11].
In robotic manipulation, CL is often studied with re-
inforcement learning (RL) or imitation learning (IL). Li
et al. [12] study dexterous manipulation in simulation us-
ing an offline CRL student–teacher framework with replay.
LEGION [13] accumulates knowledge from a continuous
task stream through a Bayesian nonparametric knowledge
space, a SAC policy, and experience replay, while using
language embeddings to infer tasks in long-horizon settings.
CLARE [14] adds encoder-decoder adapters to a frozen flow-
matching vision-language-action (VLA) model, expanding
only when a feature-novelty score indicates a new task and
routes without task IDs. SPECI [15] builds a self-evolving
skill codebook with frozen prior entries and decomposes
shared and task-specific parameters. COLADA [16] freezes
an action-chunking transformer backbone, learns one LoRA
adapter per skill from teleoperated demonstrations, and ac-
quires missing skills through grounded human dialogue.
While these methods are effective, many rely on large
frozen VLA backbones that are costly to train, store, and de-
ploy. In contrast, we use a PNN composed of compact task-
specific expert policies, connected through LoRA-style low-
rank lateral adapters [5]. This design emphasizes selective
forward transfer across both tasks and robot embodiments, a
setting not addressed by the above methods.
B. LLMs as High-Level Planners for Long-Horizon Manip-
ulation
Recent work increasingly uses LLMs to decompose
natural-language commands into sub-goals rather than to
generate low-level robot actions directly. Huang et al. [17]
prompt a frozen LLM to map household goals to mid-level
actions from a fixed vocabulary. LEAGUE++ [18] com-
bines task-and-motion planning with SAC, using an LLM
to produce symbolic operators and design dense rewards,
while warm-starting each new policy from the embedding-
nearest prior skill. CLIMB [19] constructs a symbolic PDDL
world model and introduces new predicates after execution
failures. LRLL [20] grows a library of LLM-written code
skills through a gradient-free wake–sleep procedure. Tan et
al. [21] decompose long-horizon tasks over a tree-structured
skill library with GPT-4V perception, querying a human
when a skill is unavailable. LCB [22] represents sub-goals
as learnable latent tokens, but fine-tunes the LLM end-to-
end and couples it to a single monolithic policy. These
approaches similarly use LLMs primarily for high-level
planning rather than direct control. Our framework differs by
using a frozen local LLM to decompose tasks, select among
learned expert policies, and request that a new expert be
trained when no suitable expert is available.

B. Reinforcement Learning Training
Each new column is trained with SAC [6], an off-policy
maximum-entropy actor–critic method, augmented with a
behavior-cloning (BC) loss from the task demonstrations Dn.
The actor is the newly added PNN column πθn described in
Sec. IV-A. It is trained with two critics, Qϕ1 and Qϕ2, and
their delayed target networks. After training, only the actor
column is frozen and added to the expert library.

Training batches are formed from both online replay and

LoRA factors An, Bn use weight decay λL, and the column-
specific layers f n use the base optimizer configuration.
Gradients are norm-clipped for stability. Once the evaluation
success rate remains above a preset threshold, the column is
frozen and the learner proceeds to the next task.
C. LLM-Based Planning
At deployment, the expert library is coordinated by
a frozen, locally served LLM, Qwen2.5-7B [23] running
through Ollama. The LLM is never fine-tuned and outputs
only structured JSON decisions, not low-level robot actions.
Routing is possible because each expert is stored with
a short natural-language descriptor of its capabilities. For
example, box-close-v3 is associated with skills such
as reach, grasp handle, and pick-place. Expert selection is
therefore performed in language space over skill descriptors
rather than over policy parameters, and the library persists
across sessions so each deployment starts from all previously
acquired experts.
The planner operates in two stages, following Sec. III.
First, during decomposition, it receives a compound instruc-
tion L and a catalog of available environments, then returns
an ordered list of sub-goals, each paired with a candidate
skill. Second, during routing and supervision, it selects an
expert for the current sub-goal by comparing the sub-goal
description with the library descriptors. Based on the running
success rate, the required threshold, and the remaining switch
budget, it issues one of three decisions: keep expert,
switch expert, or train new expert.
Execution proceeds one sub-goal at a time in a long-
horizon environment where each sub-goal is presented in its
corresponding scene. The selected expert is rolled out closed-
loop on the robot state for a small number of trials, and the
sub-goal is accepted if it succeeds in the majority of them.
If it fails, the LLM switches to the next candidate expert.
When the switch budget is exhausted and no existing expert
reaches the required performance, the framework invokes a
train-on-failure fallback in which a new PNN column is
added and trained for that skill, re-evaluated on the sub-
goal, and then registered with its descriptor in the library.
Thus, the skill library grows only when the current experts
are insufficient, while planning remains symbolic and control
remains learned.
D. Cross-Embodiment and Real-Robot Transfer
All embodiments considered in this work are controlled
through the same task-space interface where each policy
outputs an end-effector displacement and a gripper command
[∆x, ∆y, ∆z, g], while the robot’s low-level controller con-
verts this command into joint motion. This shared interface
allows a column trained on one robot to serve as a lateral
parent for a new column on another embodiment. To learn a
skill on a target platform, such as a Robosuite Panda, UR5e,
or real FR3, we append a new column and connect its LoRA
laterals (Eq. 3) to the previously frozen experts, including
the 12 MetaWorld columns and any Robosuite columns
learned later. During training, the new column learns which
prior experts to reuse and which lateral signals to suppress,
reducing interference from unrelated skills.
Since target demonstrations from teleoperation or real
robots are limited, the new column is trained by imitation
using a flow-matching policy [24] from N demonstrations.
Instead of directly regressing actions, the policy learns a
state-conditioned velocity field over the action space. At
deployment, an action is generated by sampling from a
Gaussian prior and integrating this velocity field for a fixed
number of Euler steps; the resulting endpoint is used as
the commanded [∆x, ∆y, ∆z, g] (along with a 3D rotation
vector for the complete pose experiments), which is further
sent to the low-level controller.

B. Model Architecture & Baseline Methods
Each PNN-LoRA column contains four fully connected
blocks. A 39-D input is passed through three 400-unit ReLU
layers and mapped to an 8-D output, representing the mean
and log standard deviation of the action distribution. The
MetaWorld library contains 12 such columns, trained with
the objective in Eq. 5. We use Adam with learning rate 10−3
for the gates and 10−4 for the LoRA factors and column-
specific layers, with weight decay 10−3 applied to the LoRA
factors. Training uses discount factor 0.99, batch size 256
split equally between online and demonstration data, and
λBC = 2. The two critics are independent three-layer 400-
unit networks and are discarded after the corresponding actor
column is trained and frozen.
The Robosuite and real-robot columns use the same ar-
chitecture but are trained only from demonstrations using
conditional flow matching. Their 39-D input contains the
robot-object state, the intermediate action sample, and the
flow time. We train these columns with Adam for 300 epochs

C. MetaWorld Experiments
A continual learner should use previously acquired skills
to learn new ones more quickly and reliably. We therefore
evaluate PNN-LoRA on the 12-task MetaWorld sequence,
where tasks are learned sequentially and compared against
the CL baselines and a standalone policy trained from scratch
for every task.
Figure 3 shows evaluation success versus environment
steps for each task. Except for the first task, where no
previous columns are available, PNN-LoRA converges faster
than the standalone policy, vanilla PNN, and the other CL
baselines. This can be attributed to the direct effect of
positive forward transfer through the gated LoRA laterals,
as well as to the selective gating mechanism that preserves
useful representations while excluding interfering ones. The
effect is most visible on difficult tasks. In assembly, for
example, most baselines fail to learn, while PNN-LoRA
reaches high success and even converges faster than the
standalone policy by reusing earlier manipulation skills.
The faster convergence also translates into strong final
performance. Table I reports the final per-task success rates.
PNN-LoRA achieves optimal performance on nearly every
task and the highest mean success across the sequence.
Several baselines collapse on contact-rich tasks such as box-
close and assembly, whereas PNN-LoRA remains stable. It
also outperforms vanilla PNN and the standalone policy on
most tasks, with the main exceptions being reach and push,
where DEN and the standalone policy obtain the best scores.
These gains are achieved with a favorable model foot-
print. As shown in Figure 4, PNN-LoRA keeps storage and
trainable parameters per task close to the standalone policy

D. Cross-Embodiment Experiments
The cross-embodiment experiments evaluate whether the
expert library can transfer knowledge across both tasks and
robot platforms. Figure 6 (A) shows the per-source contri-
bution share for each target column at N ∈{10, 30, 50}
demonstrations. Two patterns emerge. First, the contribu-
tion from MetaWorld experts decreases as more target data
becomes available: from 42% to 25% on Panda-Can, and
from roughly one quarter to at most 3% on the other
targets. This indicates that the coarse cross-simulator prior is
most useful in the low-data regime. As more demonstrations
are added, the target column shifts toward more relevant
sources. Since Panda-Can is the first Robosuite task, it has
no same-simulator parent and therefore relies increasingly
on its own pathway, whose share rises from 58% to 75%. In
contrast, later Robosuite columns reuse previously learned
pick-place experts from the same task family, keeping their
own contribution nearly unchanged, such as 20% to 22% on
Panda-Bread and a constant 15% on UR5e-Bread.
Second, transfer is driven more by task similarity than by
robot identity. The Panda milk and bread columns receive
most of their transferred signal from earlier Panda pick-place
experts, particularly can and milk, because these policies
capture the same underlying manipulation pattern. The same
trend holds across embodiments, as the UR5e milk and bread
columns also reuse available Panda and UR5e pick-place
experts. This indicates that a skill learned on one robot
can support learning on another when the task structure is
shared. The main exception is UR5e-Bread at N = 10,
where the column relies more heavily on MetaWorld experts,
suggesting that the broader prior can be more useful than a
small number of same-family demonstrations at very low
data budgets.
This selective reuse leads to consistent performance gains.
Figure 7 compares success rate as a function of the number of
demonstrations for PNN-LoRA and the from-scratch MLP-
flow baseline. PNN-LoRA outperforms the baseline on every
task and at every demonstration budget, reflecting the benefit
of lateral transfer that the baseline cannot access. The largest
gains appear on bread pick-and-place, the most challenging
task due to the smaller object size, where reusable pick-place
priors are especially valuable. The improvement eventually
saturates; after approximately 30 demonstrations, the curves
flatten, with four of five tasks changing by at most 5 points
between N = 30 and N = 50, and three already peaking at
N = 40.

E. Complete Pose Control Experiments
The preceding experiments used a 4-D action space con-
taining only end-effector translation and gripper state. To
test whether the proposed continual mechanism also extends
to orientation-aware control, we replace this interface with
Robosuite’s 7-D pose command [∆p, ∆r, g], where ∆r is an
incremental axis–angle rotation expressed in the robot base
frame. Everything else, including the PNN-LoRA structure,
frozen columns, LoRA laterals, and gated transfer mecha-
nism, remains unchanged.
For this experiment, we learn three tasks incrementally
from 50 demonstrations each, along with the online inter-
action (same as metaworld training): nut assembly, door
opening, and pose-aware cereal pick-place. The resulting
policies reach 84.0%, 100.0%, and 76.0% success, respec-
tively. Transfer follows the same pattern observed in the
translation-only setting. The door-opening column strongly
gates onto the nut-assembly expert and converges in 10.6k
frames, compared with 106k frames for its parent.
Figure 5(b) illustrates this behavior. The square nut is
initialized with an arbitrary yaw, while the gripper begins 76◦
away from the only feasible grasp axis. The policy rotates
the wrist toward that axis, grasps the handle, and carries the
nut over the fixed peg, ending with less than one degree of
residual orientation error. A rollout is counted as successful
only after the nut descends over the peg.
F. Real-World Experiments
The real-world experiment evaluates the PNN-LoRA
framework, coordinated by the LLM planner, on a long-
horizon manipulation sequence using the FR3 arm (Fig. 8).
The first two sub-tasks require full pose control, including
orientation, while the remaining four sub-tasks use position
control. The robot first picks up a plastic glass and empties
its contents into a bowl, then moves to a second glass and
hangs it on a wall-mounted nail. It then opens a box by
displacing its lid, places a bowl and then a cup inside the
box, and finally restores the lid to close the box. Each stage
is executed by its corresponding expert policy.
Each expert is trained using 30 demonstrations, and
columns are added incrementally so that each new skill
can reuse previously learned frozen skills without causing
forgetting. Figure 6(B) quantifies this reuse through the gates
of the final box-close column. In this column, lateral paths
account for 80% of the measured transferred share, with
53% coming from the five preceding real-world sub-skills
and 27% from the frozen simulation experts. The remaining
20% is attributed to the new column’s own path.
During execution, a sub-task is considered complete when
the current object-pose error relative to its target falls below
a predefined threshold. This signal is returned to the LLM
planner, which uses it to decide when to advance the plan
and which expert policy to invoke next. The sub-task order
remains fixed across all real-world trials. A trial is counted
as successful only if every sub-task is completed; under this
criterion, the framework succeeds in four of five trials.
VI. LIMITATIONS & FUTURE WORK
The current framework does not use force or tactile
feedback. Consequently, the hardware evaluation is limited
to quasi-static manipulation and does not assess interactions
that require compliant force regulation. Extending the action
space to full pose control does not address this limitation
because the policies still rely primarily on visual and kine-
matic state information. Another limitation is that the current
real-world evaluation uses a fixed sub-task order.
Future work will incorporate force and tactile feedback
directly into the policy input, allowing each expert to adapt
its motion based on the measured contact state. This ex-
tension could support force modulation during grasping,
insertion, sliding, and other contact-rich tasks. We will also
evaluate more flexible long-horizon instructions, including

VII. CONCLUSION
We presented a continual robot learning framework that
grows a library of frozen PNN expert policies connected
through gated LoRA lateral adapters. The framework en-
ables selective forward transfer without forgetting and is
coordinated by a frozen local LLM for long-horizon task
decomposition and expert routing. Across MetaWorld, cross-
embodiment transfer, pose-control, and real-world experi-
ments on an FR3, the results show that reusable expert
libraries can reduce the data required to acquire new skills
while supporting compositional robot behavior.

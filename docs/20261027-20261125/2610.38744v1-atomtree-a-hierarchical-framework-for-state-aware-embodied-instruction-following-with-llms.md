## 摘要
交互环境中的具身指令跟随要求智能体解释自然语言命令并完成长时程任务。现有规划器要么依赖大量标注轨迹，要么使用少样本和零样本LLM提示，在单一串行推理过程中生成完整计划。这些方法依赖语言常识，从初始指令开始便确定一个计划，并且仅在失败后更新，从而削弱了鲁棒性和状态感知能力。我们提出AtomTree，一种使用LLM进行状态感知任务规划的分层框架。AtomTree逐步构建由子目标和动作组成的树，其中LLM在每一步根据当前符号状态决定是进一步分解，还是输出具体的低层动作。一个轻量级记忆模块会总结过去的结果，以便在后续决策中复用。当低层动作停滞时，AtomTree触发分层回溯重规划，返回父节点并根据最新状态重新生成子树计划，从而防止沿错误轨迹继续漂移。在ALFRED基准上的零样本评估中，AtomTree优于先前基于LLM的规划器。项目主页：https://zhaihaotian.github.io/atomtree-website/。

## Abstract
Embodied instruction following in interactive environments requires agents to interpret natural language commands and complete long-horizon tasks. Existing planners either rely on large labeled trajectories, or use few-shot and zero-shot LLM prompting that produces a whole plan in a single serial reasoning process. These approaches depend on linguistic common sense, commit to a plan from the initial instruction, and only update after failures, which weakens robustness and state awareness. We present AtomTree, a hierarchical framework for state-aware task planning with LLMs. AtomTree incrementally builds a tree of subgoals and actions, where the LLM decides at each step, from the current symbolic state, whether to further decompose or to output a grounded low-level action. A lightweight memory module summarizes past outcomes for reuse in later decisions. When a low-level action stalls, AtomTree triggers hierarchical backtracking replanning to return to the parent node and regenerate the subtree plan from the latest state, preventing continued drift along an incorrect trajectory. In zero-shot evaluation on the ALFRED benchmark, AtomTree outperforms prior LLM-based planners. Project page: https://zhaihaotian.github.io/atomtree-website/.

## 1. 核心问题与整体含义（研究动机与背景）

- **任务背景**：具身指令跟随（Embodied Instruction Following, EIF）要求智能体在交互式 3D 环境中理解自然语言指令，并完成长时程家务任务（如“清洗杯子并放入咖啡机”），需要联合进行视觉感知、子目标规划、导航与物体交互。
- **现有路线及其问题**：
  - 监督式端到端方法依赖大规模“指令–专家轨迹”配对数据，标注与采集成本高，跨环境泛化差。
  - 基于 LLM 的少样本/零样本规划器（如 LLM-Planner、FLARE、Socratic Planner）通常在一次串行推理中生成完整高层计划，主要依赖语言常识，从初始指令即“承诺”整套计划，仅在失败后被动重规划。
- **核心痛点**：缺乏逐步的状态感知与闭环决策，长时程任务中错误会沿单向计划累积。
- **关键实证依据**：作者在 ALFRED Valid Seen 上对 FLARE 做错误分析，按真实 PDDL 计划长度分组：
  - 长度 ≤7 时，规划错误约占 38.9%，与交互失败（35.2%）接近；
  - 长度 >7 时，规划错误升至 68.7%，成为主导失败模式；
  - 随长度阈值 k 从 5 增至 15，规划错误占比从约 50% 单调升至接近 100%（Pearson r=0.8892，p≈2.1×10⁻⁵）。
  - 结论：长时程 EIF 的主要瓶颈已从低层导航/感知/交互转向**高层任务规划本身**。
- **语言与本体鸿沟示例**：指令“Put a washed potato slice on the white table”中，“white table”并非环境本体类别，智能体需在执行中推断其对应“Dining Table”等具体实例，说明一次性计划难以应对指代歧义。
- **整体含义**：论文主张将 EIF 建模为**状态条件的分层序列决策过程**，通过增量式“分解/执行”决策与失败回溯，提升长时程规划的鲁棒性与状态感知能力。

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想

- 用 LLM 增量构建一棵由**分解节点**与**执行节点**组成的子目标树（AtomTree），而非一次性输出完整计划。
- 每个决策步仅关注一个活跃子目标节点，依据当前符号状态、当前子目标与内部记忆，决定：
  1. **继续分解**为更细粒度的有序子目标；
  2. **直接执行**一个高层原子动作。
- 失败时不在原动作上局部重试，而是**回溯到父节点**，基于最新状态与记忆重建子树。

### 2.2 状态与树结构

- 环境状态：\(s_t=(h_t,V_t)\)，其中 \(h_t\) 为手持物体（空手为 NONE），\(V_t\) 为当前第一视角检测到的物体名称集合。
- 规划树：\(T=(V,E)\)，每个节点 \(v\) 关联自然语言子目标 \(g(v)\)；根节点由高层指令 \(I_H\) 初始化。
- 决策策略：\(y_v \sim \pi(y \mid s_t, g(v), m_t)\)，其中 \(m_t\) 为内部记忆。

### 2.3 两类决策输出

- **Decompose**：输出 \((Decompose,[g_1,\dots,g_K])\)，为当前节点创建 K 个有序子节点并挂载到树中。
- **Execute**：输出单个高层原子动作 \(a_v\in\mathcal{A}\)，交由低层控制器闭环执行，随后更新状态与记忆。
- 高层动作空间：
  - 1 个分解动作：`Decompose`；
  - 2 个导航相关动作：`Navigation`、`Find`；
  - 10 个交互动作：`PickupObject`、`PutObject`、`OpenObject`、`CloseObject`、`ToggleOnObject`、`ToggleOffObject`、`SliceObject`、`HeatObject`、`CleanObject`、`CoolObject`。
- 低层控制器沿用 ALFRED 标准管线：基于 A*、Fast Marching Method 的无障碍路径规划 + 规则式交互执行器；高层计划确定后，低层执行不再依赖原始指令。

### 2.4 轻量符号记忆

- 记忆定义为 \(m_t=(S_t,H_t)\)：
  - \(S_t\)：截至目前已见物体名称集合；
  - \(H_t\)：高层动作历史，记录动作调用及最终结果，如 `Find(Apple):0`、`Navigation(Table):1`。
- 二者序列化为短文本列表，注入后续所有 LLM 调用。
- 作用：
  - 在部分可观测下提供长时程上下文，避免重复分解已完成子目标；
  - 桥接自然语言指代与环境封闭本体（如通过已见集合将“white table”落地为 `DiningTable`）。

### 2.5 分层回溯重规划

- 当低层动作返回失败（\(r_v=0\)）或在预算内停滞时：
  - 回溯到父节点 \(u=parent(v)\)；
  - 在更新后的状态与记忆下重新决策：\(y_u\sim\pi(y\mid s_{t'},g(u),m_{t'})\)；
  - 新决策可再次分解（用新子树替换旧子树）或直接执行原子动作。
- 示例：`Find(Apple)` 失败后，记忆记录到 `Cabinet`/`Drawer` 等容器候选，回溯后修订子树为 `OpenObject(Cabinet)` 再重新 `Find(Apple)`，而非反复重试原动作。

### 2.6 提示设计

- 提示包含：角色与任务、决策选项、输入信息、可用原子动作、全局规则、输出格式、少量决策引导示例。
- 强调零样本：不使用 ALFRED 轨迹训练；少量示例仅用于约束输出格式。

- **评价指标**：成功率（SR）与目标条件成功（GC）。
- **对比方法**：
  - 监督方法：FILM、CAPEAM、MCR-Agent、Prompter；

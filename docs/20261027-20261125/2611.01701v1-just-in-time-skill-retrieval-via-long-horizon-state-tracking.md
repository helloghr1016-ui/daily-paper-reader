## 摘要
大型语言模型（LLM）智能体日益依赖外部技能库来支持复杂任务执行。然而，在长时程任务中，确定需要哪些技能仍然具有挑战性。现有方法通常在执行前选择固定的技能集合，隐含地假设任务的过程性需求可以从其初始描述中确定。这一假设对长时程交互具有限制性，因为新需求会从中间观察、执行结果和新揭示的约束中涌现。这促使了即时技能检索，其随着执行的展开动态选择技能。即时技能检索前景广阔但具有挑战性：技能的效用不仅取决于当前上下文，还取决于由先前步骤塑造的演化任务状态。为此，我们提出 JitSkill，一个基于状态的框架，通过连续任务状态跟踪来应对这一挑战。通过将涌现需求与累积的任务进展相关联，JitSkill 在整个执行过程中提供过程性支持，而不将每个检索决策视为独立。在三个智能体基准上的实验证明了其在提升长时程任务完成方面的有效性。我们的代码可在 https://github.com/XMUDeepLIT/JitSkill.git/ 获取。

## Abstract
Large language model (LLM) agents increasingly rely on external skill libraries to support complex task execution. However, determining which skills are needed remains challenging in long-horizon tasks. Existing methods typically select a fixed skill set before execution, implicitly assuming that a task's procedural requirements can be determined from its initial description. This assumption is restrictive for long-horizon interaction, where new requirements emerge from intermediate observations, execution outcomes, and newly revealed constraints. This motivates just-in-time skill retrieval, which dynamically selects skills as execution unfolds. Just-in-time skill retrieval is promising but challenging: the utility of a skill depends not only on the current context, but also on the evolving task state shaped by prior steps. To this end, we propose JitSkill, a state-grounded framework that addresses this challenge through continuous task-state tracking. By connecting emerging requirements with accumulated task progress, JitSkill provides procedural support throughout execution without treating each retrieval decision independently. Experiments across three agent benchmarks demonstrate its effectiveness in improving long-horizon task completion. Our code is available at https://github.com/XMUDeepLIT/JitSkill.git/.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：基于 LLM 的智能体越来越多地依赖外部“技能库”（将成功执行轨迹编码为可复用过程）来支撑复杂推理、工具调用与环境交互。随着技能库规模增长，把全部技能暴露给智能体不再可行，技能选择因此被建模为检索问题。
- **现有范式及其局限**：
  - **执行前固定检索**（如 SkillFlow、SkillRouter、GoS、GoSkills、CaSKG、SkillAligner）：隐含假设“任务所需的过程性技能可由初始描述充分确定”。
  - **执行时局部检索**（如 SGDR、WebXSkill、CUA-Skill）：根据当前观察/局部子目标动态匹配技能，但只看局部信号。
- **核心问题**：长时程交互任务中，能力需求并非由初始指令完全给定，而是随中间观察、执行结果、新发现的约束逐步涌现。作者指出两类风险：
  1. **执行前固定检索**会遗漏执行中才显现的需求（初步实验中 Hit@3 仅 0.115）；
  2. **仅依赖局部上下文的在线检索**可能选出“局部相关但与累积进展不一致”的技能，导致作者定义的**执行漂移（execution drift）**——表现为冗余探索与执行一致性偏差。
- **整体含义**：论文主张技能检索应从“一次性规划”转向“即时（just-in-time）检索”，且检索决策必须以**持续演化的任务状态**为根据，而非孤立地对当前上下文做匹配。这为长时程智能体的动态技能调用提供了新思路。

## 2. 方法论

### 2.1 核心思想
- 提出 **JitSkill**：一个**状态锚定（state-grounded）** 的即时技能检索框架，将技能检索与技能执行统一锚定在**持续跟踪的任务状态**上。
- 任务状态 $S_t=(B_t, Z_t)$ 由两部分互补表示构成：
  - **显式状态 $B_t$**：有界结构化文本记录，保存任务目标、关键事实、已完成子任务与结果、失败尝试及反馈；
  - **潜在状态 $Z_t$**：固定大小的循环压缩表示（$m=16$ 个槽位），保留难以用固定字段枚举的跨步执行上下文。

### 2.2 关键技术细节

- **显式状态更新**：$B_t = E(u, H_{<t})$，由确定性规则从交互历史中抽取已完成操作、结果与失败（无模型调用）。
- **潜在状态更新（循环编码器）**：$Z_{t+1}=f_\theta(Z_t, D_{t+1})$，其中 $D_{t+1}$ 为新累积的“动作–反馈”块。每次只读上一状态与新块，**每步成本不随轨迹长度增长**；训练时跨步截断梯度。
- **两阶段训练**：
  1. **历史压缩预训练**：冻结基座模型，用 LoRA 适配编码器，目标 $L_{comp}=\mathbb{E}[\omega L_{rec}+\beta L_{align}+\gamma L_{disc}]$，包含三项：
     - 重建 $L_{rec}$：从压缩表示重建历史片段；
     - 对齐 $L_{align}$：用 JSD 约束压缩/原始历史对后续上下文的预测分布一致；
     - 对比 $L_{disc}$：让压缩表示匹配其来源历史、区别于其他历史。
  2. **导航联合微调**：$L_{nav}=-\mathbb{E}\sum_{k\in K} y_{i,t}(k)\log p_{\theta,\phi}(k\mid Z_{i,t},B_{i,t})$，让下一步所需技能排名第一，梯度同时更新编码器 $\theta$ 与导航器 $\phi$。
- **进度条件化技能检索**：导航器将槽位平均潜在表示与 $B_t$ 的句向量映射为查询 $q_t$，与技能描述嵌入做相似度打分（softmax 归一化），并结合当前步相关性排序，在预算 $C_K$ 内选出 $K_t\subseteq K$。
- **状态感知技能执行**：执行器冻结，仅训练轻量投影 $P_\psi$，把潜在槽位映射为执行器可读的状态 token $Z'_t=P_\psi(Z_t)$；优化目标 $L_{proj}=-\mathbb{E}[\log p_{\eta^\star}(a_{i,t}\mid u_i,o_{i,t},H_{i,t},B_{i,t},Z'_{i,t},K_{i,t})]$。执行器同时接收 $B_t$、$Z'_t$ 与选中技能，保证“选技能”和“用技能”共享同一状态。
- **闭环**：动作与环境反馈 $o_{t+1}$ 更新最近上下文、显式记录与潜在状态，进入下一步检索，形成“状态跟踪 → 即时检索 → 状态感知执行”的闭环。

## 6. 主要结论与发现

- **整体有效性**：JitSkill 在三个基准上取得最高总体成功率：SkillsBench **15.71%**（较最强基线相对提升 **20.6%**）、ALFWorld **92.38%**（+2.1%）、τ²-Bench **49.17%**（+1.7%）；相比同执行器直接执行分别提升 9.6、23.1、10.6 个百分点。
- **检索时机不足以解释收益**：JitSkill 同时超过最强执行前方法（SkillsBench 12.64%）与最强执行时方法（13.03%），说明“在执行中更新技能”还需结合累积进展才有效。
- **消融结论**：
  - 固定初始技能集下降最大（AppWorld −8.9 TGC、ALFWorld −10.7 SR）；
  - 保留在线检索但不把进度给执行器也会下降，说明“检索”与“执行”都需状态锚定；
  - 显式与潜在表示**互补**，去掉任一项下降 5.8–6.6（AppWorld）/5.9–6.3（ALFWorld）个百分点。
- **参数敏感性**：$k=3$ 最优（92.38%），$k=1$ 仍达 89.05%；预算 600→1,200 提升 8.33 个百分点，继续增大无增益，说明**中等预算即可**。
- **效率**：ALFWorld 平均步数 13.35（少于无技能 17.57、SGDR 15.03），即“更高成功率 + 更少交互”；AppWorld 每成功任务 27.4 次动作调用（比无技能少 13%）。
- **泛化**：未见 ALFWorld 环境达 88.31%（与最佳并列），比无技能高 21.4 点；换用 Llama-3.1-8B 执行器仍最高（8.10%），而逐步检索跌至 2.38%（低于无技能 6.90%）。
- **增益来源**：多阶段任务增益（+30.1 点）远大于单阶段任务（+9.7 点）；在无技能执行器耗满 30 步的困难游戏上，JitSkill 成功率 76.9% vs 1.3%。
- **技能使用行为**：JitSkill 每 episode 切换技能 7.21 次、使用 7.31 个不同技能（逐步检索仅 3.33/4.34），且注入块始终在预算内；技能库覆盖 36/37（ALFWorld）、178/195（SkillsBench）、33/33（τ²-Bench）。

## 7. 优点

- **问题刻画清晰**：明确区分“检索时机”与“任务进展锚定”，提出“执行漂移”这一可诊断的失败模式，并用初步研究（Hit@3、TGC、冗余探索、一致性偏差）量化支撑。
- **状态表示设计合理**：显式记录 + 潜在槽位的互补设计兼顾“可检查的精确事实”与“难以枚举的跨步上下文”，且潜在状态为固定大小，**每步成本不随轨迹增长**。
- **检索与执行共享同一状态**：避免“选技能”与“用技能”割裂，是相对已有工作的关键差异点。
- **工程友好**：执行器冻结，仅训练 LoRA 编码器、导航器与轻量投影；导航器开销约 0.13 s/step（ALFWorld）、1.1 s/step（AppWorld），训练约 11 分钟。
- **实验较扎实**：三 benchmark + 消融 + 敏感性 + 未见环境 + 换执行器 + 效率 + 轨迹诊断 + 案例研究；统一协议、三次运行、训练数据选参，公平性意识较强。
- **案例研究具体**：在未见厨房场景中展示技能选择如何随“找到苹果→到达微波炉→打开冰箱”三处阶段切换而变化，并对比无技能执行器在加热阶段的循环

器在加热阶段的循环（此处应理解为：无技能执行器在同一加热阶段陷入反复探索/循环），从而直观说明状态锚定检索如何纠正执行漂移。

- **对“检索时机”与“进展锚定”做了可分离的实证**：通过“在线检索但不把进度传给执行器”等消融，把两类因素的贡献拆开，避免把收益简单归因于“更频繁检索”。
- **对成本—收益关系有量化刻画**：给出导航器每步延迟、每 episode 技能注入 token 成本、技能切换次数与技能库覆盖率，便于实际部署时评估开销。
- **失败模式诊断较细**：除成功率外还报告冗余探索率、执行一致性偏差率、错误后恢复率、每成功任务动作调用数，能部分解释“为何有效”而非只报结果。

## 8. 缺点与局限

- **绝对性能仍偏低，结论外推受限**：SkillsBench 上最高仅 15.71%，说明该基准对当前方法仍很难；此时相对提升（20.6%）虽显著，但小基数上的百分比提升容易被误读，方法在真正困难的长时程任务上的实用性尚不明确。
- **算力与复现信息不充分**：仅给出“≥48 GB 显存”“单 GPU 约 11 分钟（导航器训练）”，未说明 GPU 型号/数量、编码器预训练与联合微调的总时长、推理总开销与能耗；对想复现或做成本评估的读者不够友好。
- **基线复现可能弱于原方法**：WebXSkill 以嵌入相似度替代其 URL 图结构、SkillZip 省略 motif mining 等，若原方法最强配置更强，则对比优势可能被高估；论文虽在附录说明，但主表读者易忽略。
- **技能库构造存在偏差**：τ²-Bench 无官方技能库，技能由执行器成功轨迹蒸馏而来，相当于用“强执行器的成功经验”构造技能，可能对同源执行器（Qwen3.8-27B）更有利，跨模型公平性存疑。
- **跨执行器泛化验证不足**：仅换用 Llama-3.1-8B-Instruct 这一较小模型，且其绝对成功率仅 8.10%，无法判断方法在 GPT-4 级或其它强执行器上是否同样有效；单一主执行器也使“执行器无关性”的主张证据偏弱。
- **潜在状态的可解释性与可靠性**：$Z_t$ 为 16 槽固定压缩表示，虽经对齐/对比/重建训练，但仍缺乏对“槽位到底编码了什么”的直接分析（如槽位级探针、错误传播分析）；若压缩丢失关键约束，可能产生难以诊断的失败。
- **状态更新依赖确定性规则抽取**：$B_t$ 由规则从历史中抽取已完成操作、结果与失败，规则在开放式环境（如自由文本对话、非结构化工具返回）中的覆盖率与鲁棒性未充分讨论，可能成为瓶颈。
- **超参数与预算的敏感性结论较窄**：仅测试 $k\in\{1,3,5\}$ 与 $C_K\in\{600,1200,2400\}$，且结论“中等预算即可”基于特定基准与执行器，换任务分布后最优预算可能偏移。
- **“执行漂移”度量偏定性/局部**：冗余探索率与一致性偏差率的定义与计算细节主要在附录，主文缺少对其与最终成功率之间因果关系的更强统计检验（如中介分析）。
- **缺少与“更长上下文/更强检索器”的直接对照**：未系统比较“把完整历史直接喂给强执行器”或“更强嵌入/重排器”的简单方案，因而“状态压缩+导航”的必要性论证仍可加强。
- **训练目标权重 $\omega,\beta,\gamma$ 的选择依据**：主文给出组合目标，但权重如何选取、对下游影响的敏感性分析有限。

## 9. 启发与可拓展方向

- **状态锚定可作为通用接口**：把“显式记录 + 固定大小潜在槽位”的状态表示抽离为智能体框架的通用中间层，可能同时服务于技能检索、记忆管理、错误恢复与多智能体协作。
- **即时检索与规划的结合**：当前是“状态→检索→执行”的逐步闭环，未来可与分层规划结合，在子目标边界处做更粗粒度的技能重选，降低切换开销。
- **可解释性增强**：对潜在槽位做探针/可视化，或让显式状态与潜在状态相互校验（如潜在状态预测的约束与显式记录冲突时触发重编码），可提升可靠性。
- **技能库自动演化**：结合执行反馈对技能描述与技能库做在线增删/重写，使“检索—执行—反思”形成技能层面的闭环，而非仅在固定技能库内选择。
- **跨执行器与跨域迁移**：验证状态编码器与导航器能否在更换执行器、跨 benchmark 时低成本迁移（如仅重训投影 $P_\psi$），这将决定方法的工程价值。
- **成本感知检索**：将技能注入 token 预算、导航延迟与预期收益纳入统一目标，做自适应 $k$ 与预算分配，可能比固定 $k=3$、$C_K=1{,}200$ 更优。

## 10. 总体评价

论文的核心贡献在于**把“何时检索”与“依据什么检索”解耦并统一到持续跟踪的任务状态上**：一方面用初步研究证明“执行前固定检索”和“仅局部在线检索”都会导致可观测的执行漂移，另一方面用显式+潜在的双表示状态、检索与执行共享状态、以及两阶段训练给出一个工程上可落地（执行器冻结、训练约 11 分钟）的方案。实验覆盖三个异构基准，做了较完整的消融、敏感性、泛化与效率分析，公平性意识较强，主要结论（JitSkill 在三个基准上均最优、增益主要来自多阶段任务、显式与潜在表示互补）有较一致证据支撑。

同时，论文的说服力受限于：SkillsBench 绝对成功率很低、基线为自行复现可能弱化对比、τ²-Bench 技能库由同源执行器蒸馏、跨执行器验证仅一个小模型、算力披露不足，以及对潜在状态可解释性与规则抽取鲁棒性的分析偏少。总体而言，这是一篇**问题定义清晰、方法设计合理、实验较扎实但绝对性能与泛化证据仍待加强**的工作；其“状态锚定的即时技能检索”思路对长时程智能体的技能/记忆/工具调用研究具有较好的借鉴价值。

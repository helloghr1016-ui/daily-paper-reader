## 摘要
语言模型智能体即使配备了专家编写的技能，也常常难以应对复杂任务。此类技能编码的是陈述性知识，而成功执行需要针对当前任务的过程性知识。自然语言技能可能使条件和依赖关系隐含不显，涉及多个技能的任务还进一步要求智能体协调中间结果和执行顺序。我们提出 Think with Skills，一种在执行前训练推理模型将相关技能描述转化为任务特定伪代码规划的方法。伪代码显式表示操作、条件、中间结果和依赖关系，为从技能描述到智能体行动提供了结构化桥梁。我们构建了将任务和技能与伪代码规划及执行轨迹配对的数据，使用监督微调初始化该行为，并通过 Group Relative Policy Optimization 进一步优化端到端任务性能。在 SkillsBench 上，Think with Skills 将任务成功率从 35.0% 提升至 62.0%。这些结果表明，在执行前将专家知识过程化可显著改善技能使用。

## Abstract
Language model agents often struggle with complex tasks even when equipped with expert-written skills. Such skills encode declarative knowledge, whereas successful execution requires procedural knowledge tailored to the task at hand. Natural language skills may leave conditions and dependencies implicit, and tasks involving multiple skills further require agents to coordinate intermediate results and execution order. We introduce Think with Skills, a method that trains reasoning models to turn relevant skill descriptions into task-specific pseudocode plans before execution. The pseudocode explicitly represents operations, conditions, intermediate results, and dependencies, providing a structured bridge from skill descriptions to agent actions. We construct training data that pairs tasks and skills with pseudocode plans and execution trajectories, use supervised fine tuning to initialize this behavior, and further optimize end-to-end task performance with Group Relative Policy Optimization. On SkillsBench, Think with Skills raises task success from 35.0% to 62.0%. These results show that proceduralizing expert knowledge before execution substantially improves skill use.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：语言模型智能体常被赋予专家编写的 Agent Skills（技能包），其中包含领域知识、指令和工具使用约定，可在不改动模型参数的情况下复用。SkillsBench 显示人工整理技能平均可提升 16.2 个百分点的通过率。
- **核心问题**：技能通常以自然语言编码**陈述性知识**（是什么），而成功执行需要针对当前任务的**程序性知识**（怎么做）。作者将“拿到专家指导”与“将其转化为当前任务可执行程序”之间的落差定义为 **skill proceduralization gap（技能程序化鸿沟）**。
- **鸿沟的具体成因**：
  - 专家撰写的技能往往隐含条件、中间状态和依赖关系；
  - 技能描述的是通用流程，智能体需将其绑定到当前目标、工具、文件和观察结果；
  - 复杂任务需要多个独立编写的技能协同，需判断适用时机、连接输入输出并确定执行顺序。
- **整体含义**：仅“拥有技能”不等于“会用技能”；在执行前将专家知识显式程序化，是释放技能价值的关键环节。

## 2. 方法论

### 2.1 核心思想
- 在智能体与工具交互**之前**，先让推理模型把相关技能描述改写为**任务特定伪代码计划**，显式表示操作、条件、中间结果与依赖关系，再按该计划执行。
- 伪代码不交给外部解释器运行，而是作为**显式推理脚手架**，在环境中被模型遵循和更新。

### 2.2 伪代码规范（五要素）
1. **编号步骤**：每步描述具体操作而非笼统目标；
2. **输入与输出**：明确每步所需输入及预期产物；
3. **显式控制流**：用 if/else 表示分支、用循环表示重复；
4. **前置条件与依赖**：指明后续步骤需要哪些中间结果就绪；
5. **成功/失败/验证条件**：为产物预先定义完成判据。

### 2.3 计划对齐执行
- 执行前：识别当前步骤与分支、检查前置条件、明确预期产物；
- 执行后：对照计划中的条件验证观察结果，通过后才推进；
- 失败时：将失败归因到具体环节（错误分支、缺失前置、错误假设、执行错误），并修订受影响步骤，而非无诊断地重复动作。
- 该表示具备三性质：**技能 grounded**（操作源自专家指导）、**实例特定**（绑定当前任务/文件/工具）、**可验证**（中间产物与完成条件前置声明）。

### 2.4 技能 grounded 的数据构建流水线
- **技能来源**：从 Graph-of-Skills（含依赖、工作流、语义、替代四类关系的类型化有向图）中采样 1–3 个连通技能序列，并排除 SkillsBench 保留技能。
- **候选构建与自验证**：Draft Agent（DeepSeek-V4-Pro）自由生成任务描述、输入文件和验证脚本，须在自己的工作区跑通验证器后才进入下一步。
- **独立 Solver 评估**：强 Solver（DeepSeek-V4-Pro）与弱 Solver（Qwen3.5-35B-A3B）各尝试一次，提示词要求先输出伪代码计划再执行，形成“计划—执行”对齐轨迹。
- **结果路由**：
  - 强成功 + 弱失败 → 保留（可解且有信息量）；
  - 都成功 → Improver Agent 提高难度；
  - 都失败 → Difficulty Reducer 修复或降难；
  - 强失败 + 弱成功 → 丢弃；
  - 每个候选最多修订 3 次。
- 保留强 Solver 的成功轨迹（含伪代码与执行过程）作为 SFT 监督；弱 Solver 轨迹仅用于过滤；验证脚本作为 GRPO 的任务级奖励。

### 2.5 两阶段训练
- **阶段一 SFT**：输入为任务指令、输入文件、相关技能和可用工具；目标轨迹中伪代码紧邻对应执行阶段出现，直接监督“先计划后执行”的行为。
- **阶段二 GRPO**：从 SFT checkpoint 出发，对每个任务采样一组完整 rollout（生成伪代码 + 环境交互），由任务验证器给最终结果打分，组内归一化奖励作为相对优势，在带 KL 正则的标准裁剪目标下更新策略；奖励贯穿整个 rollout，同时优化伪代码生成与执行。

## 10. 总体评价

本文的核心贡献不在于提出新的训练算法，而在于**精准命名并系统性地填补了一个被忽视的环节**：智能体拥有技能与真正会用技能之间的“程序化鸿沟”。其解法——执行前生成任务特定伪代码、执行中按计划对齐并在失败时归因修订——概念简洁、规范具体、与现有 planning 工作有清晰区分；配套的数据构建流水线通过强弱 Solver 难度校准与自验证，把“计划—执行”对齐轨迹的获取工程化，并以 SFT + GRPO 两阶段训练落地。在单一 benchmark、单一基座模型的受控设置下，27.0 个百分点的绝对提升与逐级消融提供了较直接的因果证据。

但论文的证据强度仍受限于：实验覆盖面窄（一个 benchmark、一个模型、约千级训练样本）、缺少统计显著性报告、伪代码各要素与其他中间表示未做细粒度对照、过程级机制未被直接测量，以及算力与成本信息缺失。因此，更稳妥的解读是：**“先程序化再执行”是一个高性价比、值得在更多模型与任务上验证的通用范式**，而非已被充分确立的结论。后续工作若能在跨模型/跨技能库泛化、伪代码形式消融、过程指标度量与训练规模扩展上补足，将显著增强该方向的说服力。

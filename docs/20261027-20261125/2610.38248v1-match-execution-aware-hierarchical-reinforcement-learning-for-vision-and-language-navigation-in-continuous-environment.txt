MATCH: Execution-Aware Hierarchical Reinforcement Learning for
Vision-and-Language Navigation in Continuous Environment
Shuhao Ye1, Yufei Wei1, Demao Wang1, Shichao Zhai1, Rong Xiong1, Yue Wang1†
Abstract— Vision-and-Language Navigation in Continuous
Environments (VLN-CE) requires instruction-consistent plan-
ning and reliable execution under collision constraints. Yet
many hierarchical approaches optimize the planner while
keeping execution fixed. We introduce MATCH, a frame-
work that jointly learns a language-conditioned planner and
a goal-conditioned primitive-action executor. An execution-
aware topological graph represents start-dependent execution
options and integrates executor value estimates with realized
outcome memory, enabling the planner to select execution
requests and refine their targets through bounded continu-
ous offsets. A transition-aware dense macro reward balances
ordered progress along the reference route against execution
residual, encouraging executable requests without substituting
local success for instruction following. A staged curriculum
culminates in synchronized on-policy updates, with the executor
learning on planner-generated requests and the planner adapt-
ing its requests to the executor’s current behavior. With 0.5B
parameters, MATCH achieves state-of-the-art performance on
the R2R-CE and RxR-CE benchmarks. Preliminary real-robot
deployments further demonstrate its practical potential.

learn to avoid a difficult doorway and select an alternative
target, but the same experience does not teach how to handle
that doorway more reliably (Fig. 1b). Our insight is to extend
the learning loop beyond macro-level planning to include
micro-level execution: navigation experience should help to
co-optimize the planner and executor, not just improve the
planner’s ability to work within its limits.

Hierarchical reinforcement learning (HRL) [9] provides
a natural framework for this joint adaptation. The planner
determines the requests on which the executor learns, while
the executor shapes the transitions those requests realize. The
challenge is to couple these adaptations so that the executor
learns on planner-generated requests and the planner selects
requests that produce instruction-consistent progress under
the current execution policy, rather than merely favoring easy
targets. This calls for grounding macro-action learning both
in the current executor and in the task contribution of its
realized transitions.
We address this challenge with MATCH (Macro-Action
Transition Coupling for Hierarchical RL) (Fig. 1c), which
jointly learns a language-conditioned planner and a goal-
conditioned executor. We implement its decision interface
within the graph-based VLN-CE architecture [2], where
waypoint proposals define candidate frontiers for an online
topological planner. To ground the planner’s requests in the
executor’s evolving capabilities, we develop an execution-
aware topological graph. In this graph, edges from different
visited nodes to the same frontier represent distinct execution
options, since execution outcomes depend not only on the
destination but also on the starting location. Each edge car-
ries the executor’s value estimates over a target neighborhood
before execution and records the realized outcome memory
afterward. The planner pairs edge selection with a bounded
continuous target offset within this evaluated neighborhood,

allowing it to refine an execution request rather than merely
accept or reject a fixed waypoint.
To learn which execution requests are useful for the task,
we introduce a transition-aware dense macro reward based
on their realized transitions. Each macro action receives
credit for the ordered progress along the reference route,
minus the execution residual—the remaining target-reaching
distance—with both measured in meters. The progress term
encourages the planner to advance along the route, not just
choose easier targets. The residual gives the planner direct
feedback on each request’s execution difficulty, rather than
leaving it implicit in final task outcomes. This encourages
executable requests without making local success a substi-
tute for instruction following. The executor is rewarded for
progress toward assigned target. A staged curriculum fol-
lowed by synchronized on-policy updates lets both policies
adapt through shared navigation experience.
Our main contributions are:
• We propose MATCH, to our knowledge the first
VLN-CE framework to jointly optimize a language-
conditioned planner and a primitive-action executor
through HRL, with both policies learning from shared
on-policy navigation rollouts.
• To support joint adaptation during HRL, we develop
an execution-aware topological graph that uses executor
value estimates and outcome memory to guide the
planner’s selection and refinement of execution requests.
• We introduce a transition-aware dense macro reward
that balances ordered progress along the reference route
against execution residual, encouraging executable re-
quests that advance the route.
• Using a 0.5B-parameter model, MATCH achieves state-
of-the-art performance on R2R-CE and RxR-CE, with
real-robot deployments further validating practicality.
II. RELATED WORK
A. Hierarchical Vision-and-Language Navigation
VLN-CE
[1]
requires
instruction
following
through
collision-constrained primitive actions rather than assuming
oracle transitions between predefined viewpoints. Waypoint
prediction [10] introduces intermediate spatial goals to con-
nect language-conditioned planning with movement, en-
abling discrete-environment agents to transfer to continuous
settings without predefined navigation graphs. Graph-based
methods extend planning context: DUET [11] combines fine-
grained local grounding with global topological reasoning,
while BEVBert [12] integrates metric and topological maps
for spatially grounded navigation. ETPNav [2] couples on-
line topological mapping and cross-modal planning with
a heuristic controller that tries alternative actions when
execution is blocked. DualVLN [3] learns a diffusion-based
executor conditioned on a supervised pixel-goal planner, but
does not refine the planner through RL on executor-induced
macro transitions. HSAN [13] combines supervised high-
level planning with RL-based low-level control. Ye et al. [4]
optimize topological frontier selection through closed-loop
macro-action RL while retaining a fixed controller. MATCH
differs by applying RL to both levels, jointly optimizing a
language-conditioned planner and a primitive-action executor
from shared on-policy navigation rollouts.
B. Hierarchical Learning and Execution Feedback
In state-based control, goal-conditioned HRL methods
jointly learn high-level subgoals and low-level policies [14],
[15]. HIRO [16] corrects off-policy experience to account for
changing low-level behavior, while HAC [17] uses hindsight
transitions to learn multiple policy levels in parallel. For
execution grounding, SayCan [18] uses value functions of
pretrained skills to inform language-level decisions. For
route-aware supervision and evaluation, LAW [19] aligns
corrective actions with the instructed path instead of only the
destination, while nDTW [20] measures ordered path fidelity
and can serve as an RL reward.
MATCH couples macro-action learning to both the execu-
tor’s evolving capabilities and the task contribution of real-
ized transitions. Its execution-aware topological graph uses
current executor values and outcome memory to evaluate
source–target execution options, guiding request selection
and bounded continuous target refinement. Its transition-
aware macro reward credits ordered route progress while
penalizing execution residual, providing direct feedback on
both task contribution and execution shortfall. Together, these
mechanisms support joint adaptation without treating local
target completion as the navigation objective.
III. METHOD
A. Hierarchical Formulation with a Learned Transition
Task. In VLN-CE an agent must follow a natural-language
instruction I to its goal in an unseen 3D environment. At
each step it observes a panoramic RGB-D image of 12
egocentric views and its odometry, and issues one primitive
action: move forward by ∆s = 0.25 m, turn left or right by
∆θ or stop. It succeeds if it stops within 3 m of the goal,
typically after hundreds of primitives.
Hierarchy. Following [4], we cast the task as a hierar-
chical MDP. A waypoint predictor [10] predicts navigable
waypoints around the agent, and the predicted waypoints
are accumulated online into a topological graph Gt [2]. At
macro step t the planner acts on the macro state st = (I, Gt);
its macro action commits the agent to one of the predicted
waypoints or to STOP, and an executor πL realizes it with
primitive actions before the graph is updated. The macro
transition P πL(st+1 | st, at) is thus determined by the envi-
ronment together with the executor. In [4] the executor is a
fixed heuristic, so this transition is fixed and only the planner
learns. MATCH learns both levels jointly as a hierarchical
RL agent, so the transition itself changes during training,
and the planner is adapted to this in three ways: it observes
the executor’s expected performance before committing to a
target and the actual outcome afterwards, it can adjust the
target within the neighborhood it has evaluated (Sec. III-C),
and its reward is designed to account for both task progress
and execution residual. (Sec. III-D).

Workflow (Fig. 2). At each macro step, the planner scores
every active edge e = (j, c) from a visited node vj to a
frontier c, together with STOP, and samples an edge and a
continuous offset η; together they define a 2D target ξ near
the location the edge points to. If the agent does not stand at
vj, it first returns there by replaying the primitive sequences
stored on the tree edges along the path; this needs no
policy, so the executor is responsible only for reaching new
targets. The executor then drives toward ξ until it declares
REACHED or exhausts its decision budget (TIMEOUT).
Wherever it stops, a new visited node is created, the executed
edge stores the outcome, waypoints predicted from the new
node extend the graph, and every new edge is annotated with
the executor’s value estimates for targets around it.
B. Goal-Conditioned Executor
Interface. The executor receives no language; a sub-task
is specified only by a 2D target ξ relative to the start node.
The executor acts in decisions, each of which expands to
several primitives. At decision k it observes a single forward
depth view, the distance ρk and bearing θk of the target
from odometry, and its previous decision. A decision is either
REACHED, which ends the sub-task, or MOVE(m) for one
of M (M = 360◦/∆θ) evenly spaced headings: the agent
turns to heading m with the fewest turn primitives and then
moves forward once. A sub-task also ends after Kmax = 16
decisions (TIMEOUT).

C. Execution-Aware Topological Graph and Macro Actions
Graph. Gt has three kinds of elements. A visited node
vj is created at the start pose and at the end of every
execution, wherever the agent stopped; it stores the agent’s
pose and the panorama observed there. Every visited node
except the root has exactly one parent, the node from which
the agent reached it, so the visited nodes form a tree; the
tree edge from the parent stores the primitive sequence of
that execution and its outcome memory, defined below. A
frontier c is a predicted waypoint that has not been visited
yet; waypoints predicted from different visited nodes that
lie within a merging radius of each other are merged into
one frontier. An active edge e = (j, c) connects a visited
node vj to a frontier c that was predicted from vj. Since
a frontier merges the predictions of several nodes, the edge
stores where vj itself predicted it: this position ae is the
anchor of the edge, and ˆue is the unit direction from vj
to ae. The graph is updated whenever a new visited node
is created, by sorting the waypoints predicted from it into
three cases. A waypoint that lies close to a visited node is
discarded. A waypoint that lies close to an existing frontier is
merged into it, and a new active edge connects the new node
to that frontier. Any other waypoint becomes a new frontier,
connected to the new node in the same way. The executed
edge is removed, and if the agent reached its frontier, the
frontier is removed as well. Edges are kept specific to their
parent node because the outcome of an execution depends
not only on the target but also on where it starts.

D. Transition-Aware Macro Reward
To help the planner accurately assess the difficulty of
the requests it issues to the executor, we incorporate the
execution residual of each request into the macro reward.
However, it may also encourage the planner to generate
overly simple requests, disregarding task progress. A com-
plementary reward that measures task progress is therefore
necessary to balance this tendency. How to quantify progress
at each macro step is thus an important engineering problem.
We first introduce our solution, ordered route coverage, and
then describe how it is integrated into the macro reward.
Ordered route coverage. The progress should measure
motion along the reference route. Alignment-based metrics
such as nDTW [20] may appear to be a natural choice.
However, they measure how closely the executed trajectory
aligns with the reference route as a whole, rather than how
much progress has been made along that route.

IV. TRAINING
Training the two levels of MATCH jointly from the start
is not practical. With an untrained executor, the value fields
carry no information and the planner’s targets are never
reached; with an untrained planner, the executor is requested
to arbitrary places. Neither level can learn from the other
until both are competent, so we train in three stages as below.
A. Stage 1: Parallel Warmup
Planner. The planner uses the same data and methods as
Revisiting [4] for offline pretraining. No executor is involved
at this stage, so the value fields and outcome memories of
all edges and nodes are filled with a learned placeholder, and
the offset head and the value head are not trained. What the
planner learns here is grounding: how the instruction and the
panoramas relate to the choice of a frontier.
Executor. The executor is pretrained on sub-tasks gen-
erated offline. A sub-task consists of a start node sampled
from the expert trajectories and a 2D target generated by
the waypoint predictor [10]. Supervision comes from the
simulator’s oracle shortest path follower with access to the
navigable mesh. The executor is first trained by behavior
cloning on the teacher’s decisions, then by DAgger, and
finally by PPO [21] with the reward of Eq. (1).
B. Stage 2: Online Imitation with a Frozen Executor
The planner is now trained by DAgger with the same
teacher supervision as in [2]. The frozen executor of stage 1
realizes its macro actions, so the planner faces the states a
real executor produces and receives value fields and outcome
memories as inputs. These inputs are not yet clearly related


to the decisions: the teacher has no mechanism to reflect the
executor’s reachability in its labels, so imitation can only
accustom the planner to the form of the execution feedback,
while learning to use it is left to the stage 3. For the same
reason the offset head is not trained here and starts stage 3
from a zero offset, by initializing the last layer of the offset
mean head to zero. After imitation, VH is fitted to the returns
of Eq. (7) on autonomous rollouts of the frozen policy.
C. Stage 3: Joint Hierarchical Reinforcement Learning
Both levels are now trained by PPO on the same experi-
ence. Each iteration collects a batch of full episodes with
both policies sampling, uses it for one epoch of updates
of both levels, and discards it. The episodes of this stage
are held out from stage 2, so that the planner does not re-
encounter episodes it imitated: 80% of the training episodes
are used for stage 2 and the remaining 20% for stage 3.
Planner update. The planner is updated on macro steps of
the batch, with the importance ratio of the joint macro-action
probability πE(e | st) πoff(η | e, st) and advantages estimated
by GAE over macro steps from the reward of Eq. (7) with
γH = 1. The loss is the clipped PPO surrogate with a value
loss on VH and an entropy bonus on πE and πoff.
Executor update. The executor is updated on the deci-
sions of all sub-tasks in the batch, with the importance ratio
of the decision taken under πL and advantages estimated by
GAE within each sub-task from the reward of Eq. (1) with
γL = 1. The loss is the clipped PPO surrogate with a value
loss on VL and an entropy bonus. Thus, executor training
follows the starting-state and target distribution encountered
under the current hierarchy, rather than a separate, fixed
distribution of execution sub-tasks.
V. EXPERIMENTS
A. Experimental Setup
Benchmarks and metrics. We evaluate on the val-unseen
splits of R2R-CE [22] and RxR-CE [23] in habitat simula-
tor [24]. R2R-CE provides English instructions for shortest-
path routes. RxR-CE provides multilingual instructions for
routes that are substantially longer and possibly non-shortest
paths. The two benchmarks also differ in their agents: R2R-
CE has ∆θ = 15◦and allows sliding along obstacles,
whereas RxR-CE’s ∆θ = 30◦, has a larger agent radius
and forbids sliding. We report in the standard navigation
metrics: navigation error (NE), oracle success rate (OS),
success rate (SR) and success weighted by path length (SPL)
and normalized dynamic time warping (nDTW).
Implementation details. Architectural details are given
in the appendix. αprog and αtime in Eq. (1) are 1.0 and
0.1 respectively. For Training Stage 3, Each iteration of the
joint stage collects 128 episodes with the current policies
and performs one update of both levels. We totally run 4000
iterations. PPO uses a clipping range of 0.2, GAE with λ =
0.95, a value-loss coefficient of 0.5 and an entropy coefficient
of 0.01. Training runs on 4 NVIDIA RTX 5880 GPUs and
takes about 70 h for the planner and 100 h for the executor
in stage 1, 90 h in stage 2 and 120 h in the joint stage.
B. Comparison with the State of the Art
Table I compares MATCH with previous methods on both
benchmarks.
The first group follows the same high-level architecture as
MATCH: a planner selects frontiers on a topological graph,
while low-level execution is handled by a heuristic controller.
Revisiting is the strongest of them but MATCH improves
over it on every metric, by 0.9 SR and 4.2 SPL on R2R-CE
and by 5.4 SR and 3.2 nDTW on RxR-CE, at a comparable
model size.
The second group contains recent methods built on large
vision-language models. VLN-R1 and StreamVLN output
primitive actions directly from the language model. Du-
alVLN is a dual-system method whose VLM grounds a
pixel goal in the current image and a diffusion policy
executes it. It is therefore the closest in spirit to MATCH,
but its two systems are trained sequentially and the high-
level model receives no feedback from the low-level one.
MATCH surpasses DualVLN by 4.7 SR and 3.0 SPL on
R2R-CE and by 6.3 SR and 2.4 SPL on RxR-CE, with
about 1/10 of its parameters. OmniNav reports its results with
a teleporting executor that follows the predicted trajectory
waypoints without executing primitive actions. To compare it
under the same conditions as every other method in the table,
we reproduce its evaluation with the rotate-then-forward
executor. Under this setting MATCH surpasses it by 2.9 SR
in R2R-CE and 3.0 SR in RxR-CE.

Training. The result of “w/o joint HRL” first shows the

the evolving planner, rather than adapting the planner alone

almost the same accuracy as synchronous updates. But it
takes 200 h instead of 120 h, because the episodes collected
while one level is trained are not used to train the other.
Synchronous training is thus the more economical way of

E. Real-World Deployment
We deploy MATCH on a TurtleBot 4 equipped with an
elevated Seeker multi-camera system that provides four-view
panoramic RGB observations. An onboard NVIDIA Jetson
Orin interfaces with the camera system and handles image
processing and transmission, while model inference is per-
formed on a remote server equipped with an NVIDIA RTX
3090 GPU. All system components communicate through
ROS [27]. Since MATCH additionally requires panoramic
depth and robot pose as inputs, we use FoundationStereo [28]
to estimate depth for the four camera views. For localization,
we first construct a map of the environment using SLAM [29]
and then estimate the robot pose online using Adaptive
Monte Carlo Localization (AMCL) [30]. Importantly, the
pre-built map is used only for localization and visualization
and is never provided to MATCH.
The physical sensing configuration differs from the origi-
nal MATCH setup, which represents each graph node using
12 visual tokens. We therefore first retrain the waypoint
predictor using four-view observations. For the planner, we
introduce a lightweight attention-based adapter that lifts the
four tokens associated with each node to the original 12-
token representation, while leaving the remainder of the
planner architecture unchanged. We train this adapter and the
modified planner by distilling knowledge from the original
MATCH planner, followed by Stage 3 joint training in
simulation using the same four-view camera configuration
as the real robot.
During real-world deployment, the planner operates at
approximately 0.1 Hz, whereas the executor runs at approx-
imately 1 Hz. We evaluate the complete system over four
episodes in indoor environments, with results summarized


in Fig. 5. The results indicate that MATCH transfers effec-
tively from simulation to the physical platform and exhibits
promising sim-to-real generalization.
VI. CONCLUSION
We presented MATCH, a hierarchical reinforcement learn-
ing framework that improves VLN-CE navigation through
joint adaptation of a language-conditioned planner and a
goal-conditioned executor. Its execution-aware graph, contin-
uous target refinement, and transition-aware reward connect
the executor’s evolving capabilities to progress along the
instructed route. Ablation studies support the benefits of
joint adaptation and execution feedback, while highlighting
the importance of balancing route progress with execution
residual. Real-world deployment across four indoor real-
robot episodes also suggests promising sim-to-real transfer.
Together, these findings support learning what to execute
and how to execute it through shared experience, rather than
adapting planning alone to a fixed controller.

Appendix: Network Architecture of MATCH
I. NETWORK ARCHITECTURE
This appendix specifies the networks that implement the
two levels of MATCH. Their interfaces are fixed in the main
paper: the planner maps the instruction and the execution-
aware graph Gt to a distribution πE over the active edges and
STOP, an offset distribution πoff for the selected edge, and a
value VH; the executor maps its observation and the relative
target to a distribution over decisions and a value VL, and this
value, evaluated at the start of a sub-task for targets around
an anchor, is the value field of an edge. Sections I-A–I-D
describe the planner from the encoders to the heads, Sec. I-
E the executor, and Table I lists all modules with their sizes,
initialization and training status in each stage. Throughout,
d = 768 denotes the hidden size of the planner and MLP a
two-layer perceptron with a ReLU in between.
A. Encoders
RGB. Each of the 12 views of a panorama is encoded by
the SigLIP2 ViT-B/16 image encoder [1] at a resolution of
224 × 224; its pooled embedding is projected linearly to d.
The encoder is frozen in all stages.
Depth. Depth views, at 256 × 256, are encoded by the
ResNet-50 depth encoder of the DD-PPO PointNav agent [2],
including the output projection of that agent, which maps
the ResNet features to a 512-dimensional vector; the planner
projects this vector linearly to d. The same frozen encoder
serves the executor (Sec. I-E), so a depth view is encoded
once and used by both levels.
Instruction. The instruction is encoded by InfoXLM-
base [3], a 12-layer multilingual Transformer with hidden
size 768 whose output tokens are used directly as the
instruction tokens of the planner. InfoXLM is fine-tuned in
every stage in which the planner is trained.
Panorama. For each view v of a visited node j, the
RGB feature, the depth feature and a sinusoidal encoding
of the view’s heading relative to the node’s heading are
concatenated and projected to d. The 12 vectors then pass
through two Transformer encoder layers with self-attention
over the views (12 heads, feed-forward size 4d). The outputs
are the view tokens ˜z(j)
v , v = 1, . . . , 12.

E. Executor Network
The executor is a recurrent point-goal policy with the
architecture of the DD-PPO PointNav agent [2], ResNet-50
followed by a two-layer LSTM with hidden size 512, adapted
to the decision space of MATCH.
Inputs. At decision k the executor receives three inputs.
The forward depth view is encoded by the shared frozen

is encoded by a linear layer from [ρk/ρnorm, cos θk, sin θk],
where ρk and θk are the distance and bearing of the target
computed from odometry, into 32 dimensions. The previous
decision is encoded by a learned embedding table with M+2
entries, one per heading, one for REACHED and one start
symbol used at the first decision, also into 32 dimensions.
The three encodings are concatenated and fed to the LSTM.
Outputs. Three linear heads on the LSTM state output
the REACHED logit, whose sigmoid is pR, the M heading
logits, whose softmax is πdir, and the value VL. At test time
the executor acts greedily, taking REACHED if pR exceeds
every (1 −pR) πdir(m) and the most probable heading
otherwise.
Initialization. The depth encoder with its output projec-
tion, the target encoder and the LSTM are initialized from
the released DD-PPO checkpoint (ResNet-50 + LSTM-512),
whose point-goal input has the same distance-and-bearing
form as our target and whose previous-action embedding
occupies the same input slot as ours. The previous-decision
embedding table, the two policy heads and the value head are
new, because the decision space and the reward of MATCH
differ from those of PointNav, and are trained from scratch.
The depth encoder is frozen; the target encoder, the LSTM,
the embedding table and the heads are trained in stages 1
and 3.
Initial state and value field. A sub-task starts with the
LSTM state set to zero and the previous decision set to the
start symbol. The first depth view is the view of the start
node that faces the anchor, taken from the node’s cache, so
no additional rendering is needed; from the second decision
on, the executor observes the forward view rendered after
each move. The value field of an edge is VL evaluated in
exactly this initial state for the NF targets ae + Beηn. Since
the depth feature and the LSTM state are shared by all NF
targets and only the target encoding differs, the field of an
edge costs one batched pass of the target encoder, the LSTM
and the value head, and the fields of all new edges of a node
are computed in a single batch.

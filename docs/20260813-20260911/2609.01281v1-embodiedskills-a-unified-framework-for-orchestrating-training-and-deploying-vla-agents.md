## 摘要
视觉-语言-动作（VLA）模型将视觉观察和语言指令直接映射为机器人动作，但长周期任务需要的不仅是动作预测。智能体必须随着物理状态演变协调感知、规划、执行、进度验证与恢复。动作预测或模型生成的技能决策本身并不能保证所提出的操作在当前状态下有效，也不能保证其结果会得到验证。我们提出 EmbodiedSkills，一个统一框架，将每个技能决策视为一个执行提案：运行时在执行前检查其前提条件，并在执行后验证结果。共享的可执行技能接口将高层技能选择、有界低层 VLA 执行和动作后验证连接在单一智能体循环中。由于该接口保持不变，低层 VLA 策略可以被替换或调整，而无需改变智能体循环。该接口还将规划、执行、验证和恢复事件记录为结构化轨迹，为各个组件提供监督，并可在有交互反馈时支持可选的在线自适应。我们在 RoboTwin 2.0 和 LIBERO 上使用 Qwen3-VL 和 OpenPI/pi0.5 实例化 EmbodiedSkills。任务自适应低层 VLA 策略在 50 个 RoboTwin 2.0 任务上平均成功率达 86.20%，在四个 LIBERO 套件上达 97.40%。这些结果确立了 EmbodiedSkills 中使用的任务自适应低层 VLA 策略的执行性能。在四个依赖记忆的 RMBench 任务上，同样的任务自适应执行方法平均成功率为 12.5%。该框架提供了一个可训练和可检查的智能体层，用于将这些策略转化为闭环具身系统。

## Abstract
Vision-language-action (VLA) models map visual observations and language instructions directly to robot actions, but long-horizon tasks require more than action prediction. An agent must coordinate perception, planning, execution, progress verification, and recovery as the physical state evolves. An action prediction or a model-generated skill decision does not, by itself, guarantee that the proposed operation is valid in the current state or that its outcome will be verified. We propose EmbodiedSkills, a unified framework that treats each skill decision as an execution proposal: the runtime checks its prerequisites before execution and verifies the outcome afterward. A shared executable-skill interface connects high-level skill selection, bounded low-level VLA execution, and post-action verification within a single agent loop. Because this interface remains fixed, low-level VLA policies can be replaced or adapted without changing the agent loop. The interface also records planning, execution, verification, and recovery events as structured trajectories, which provide supervision for individual components and can support optional online adaptation when interactive feedback is available. We instantiate EmbodiedSkills with Qwen3-VL and OpenPI/pi0.5 on RoboTwin 2.0 and LIBERO. Task-adapted low-level VLA policies achieve an average success rate of 86.20% across 50 RoboTwin 2.0 tasks and 97.40% across the four LIBERO suites. These results establish the execution performance of the task-adapted low-level VLA policies used in EmbodiedSkills. On four memory-dependent RMBench tasks, the same task-adapted execution approach achieves 12.5% average success. The framework provides a trainable and inspectable agent layer for turning these policies into closed-loop embodied systems.

## 2. 方法论

### 2.1 核心思想：策略-运行时分离

- 高层代理策略提出**结构化技能决策**，低层 VLA 策略生成**有界动作块**，运行时负责**强制先决条件、制品新鲜度、动作有效性和合法状态转换**。
- 共享技能接口固定，因此低层 VLA 策略可以替换或适配，而不必修改智能体循环；同时该接口将规划、执行、验证、恢复事件记录为结构化轨迹，用于组件监督和可选在线优化。

### 2.2 关键概念与形式化

- **智能体状态**：  
  \( s_t = (z_t, M_t, H_t) \)  
  其中 \( z_t \) 是当前阶段，\( M_t \) 是可用任务制品集合，\( H_t \) 是有序循环轨迹。
- **决策接口**：策略从状态相关动作集中选择，决策类型包括：
  - `RunSkill(k, q)`：执行技能 \( k \) 并携带载荷 \( q \)；
  - `AdvanceStage`：推进阶段；
  - `FinishRun`：终止。
- **可执行技能契约**：  
  \( k = (X_k, Y_k, pre_k, exec_k, post_k, fail_k) \)  
  定义输入/输出模式、先决条件、执行操作、结果状态更新和失败映射。制品携带来源和新鲜度信息，防止过期观测、计划或动作被静默复用。
- **六个阶段**：`Observe`、`Plan`、`Preflight`、`Execute`、`Verify`、`Recover`。这些阶段不是固定顺序流水线，策略可根据状态证据回访、修订或进入恢复。
- **守卫式运行时转换**：
  - 技能提案守卫：检查阶段匹配、技能可接受性以及所有先决条件；
  - 推进守卫：检查当前阶段是否已产生后继所需证据；
  - 终止守卫：仅接受 `FinishRun`。
  - 被阻止的决策及其证据会被记录，而不是被静默转换成物理动作。
- **有界动作执行**：低层 VLA 策略根据活跃子目标、当前观测、机器人状态和就绪证据生成有界动作块  
  \( a_t = (\tau_t, U_t, H_t, \eta_t) \)  
  运行时只接受满足动作类型、维度、数值有效性、执行视野以及与当前子目标和观测一致的动作块。
- **验证与恢复**：验证器仅基于最新动作后的证据评估当前子目标，从  
  \( V = \{ \text{Advance}, \text{Continue}, \text{Reobserve}, \text{Replan}, \text{Recover}, \text{Finish} \} \)  
  中选择语义路由。恢复使用相同显式任务状态和失败证据生成修订后的执行上下文，再次经过检查后才允许物理动作。
- **算法流程**：Algorithm 1 给出六阶段守护循环：构建紧凑上下文、计算可接受技能、查询策略、按守卫执行/阻止、记录决策与结果、返回最终状态与轨迹。

### 2.3 训练机制

- **组件级监督适配**：
  - 规划器：将任务指令和视觉上下文映射为有序可执行子目标，不包含模拟器特定的控制细节。
  - 低层 VLA 策略：用子任务级演示单独适配，部署时通过 Execute 接口接收相同子目标条件上下文。
  - 高层调度器：基于 Qwen3-VL 在部署一致的决策轨迹上监督，保持低层 VLA 策略冻结，隔离 SFT 阶段与连续控制学习。
  - 验证器可以从执行后观测和子目标完成标签中学习。
- **部署一致的训练样本**：输入包括任务指令、当前阶段、可见图像、紧凑运行时状态、可接受技能集合和最近历史；只对学习组件生成的 token 计算损失，提示、图像、工具结果和环境消息仅作为上下文。
- **可选闭环优化**：收集交互轨迹 \( \tau \)，在保持低层 VLA 策略固定的情况下，采用分组相对策略优化（GRPO 风格）对高层策略进行在线改进；论文指出这只是可选细化，不是主要训练范式。

## 6. 主要结论与发现

- **RoboTwin 2.0**：任务自适应低层 VLA 策略平均成功率为 **86.20%**，较 LingBot-VA 报告的 π0.5 参考 **82.74%** 提升 **3.46 个百分点**；在 50 个任务中 39 个提升、1 个持平、10 个下降。最大提升出现在接触敏感和多阶段任务（如 Hanging Mug +20、Blocks Ranking Size +15、Open Microwave +15）。
- **LIBERO**：平均成功率 **97.40%**，较官方 OpenPI **96.85%** 提升 **0.55 个百分点**；四个套件全部提升，LIBERO-Long 提升最大（+1.2）。
- **RMBench**：同一任务自适应执行方法在四个记忆依赖任务上平均 **12.5%**，高于已发布基线但整体成功率很低，表明记忆依赖操作仍是挑战。
- **消融结论**：
  - Full 配置 86.20%；
  - 去掉中间验证（w/o Verify）降至 48.2%，损失 38.0 个百分点；
  - 去掉语义子任务条件（w/o Subtask）降至 34.4%，损失 51.8 个百分点；
  - 每个子任务只允许一个 32 步动作块（1 chunk）降至 19.5%。
  - 这说明**显式子任务分解、事后验证和自适应继续执行**三者在长周期任务中缺一不可。
- **框架层面**：EmbodiedSkills 提供了可训练、可检查的智能体层，能够在保持高层 AgentLoop 不变的情况下替换或适配低层策略，并将模型决策与运行时执行语义解耦。

## 7. 优点

- **清晰的设计边界**：策略负责“提议”，运行时负责“强制执行”，使失败显式化和可追踪，避免无效决策被静默转换为物理动作。
- **高度模块化**：共享技能契约将规划、验证、执行、恢复和环境适配器解耦，各组件可以独立训练、替换或使用不同模型，而不改变外围循环。
- **结构化轨迹用于训练**：部署一致的数据格式同时支持监督学习、组件适配和可选在线优化，训练与部署边界一致。
- **充分的消融实验**：通过控制变量分离子任务条件、验证和动作块继续三个关键机制的贡献，证据清晰。
- **跨基准验证**：在 RoboTwin 2.0、LIBERO 和 RMBench 三个性质和难度不同的基准上验证，显示执行接口的通用性。
- **与现有 VLA 策略互补**：不替代低层策略，而是提供智能体层来调用、验证、继续或重试它们，实用性强。

## 8. 不足与局限

- **依赖任务特定微调**：RoboTwin 2.0 上为每个任务训练独立 π0.5 策略，训练、存储和部署成本高，且与单一通用策略相比扩展性不足。
- **延迟与计算开销**：额外的高层 VLM 调用、事后

验证和运行时守卫检查会增加每次技能级决策的延迟与计算成本，论文未报告端到端推理延迟、频率或单位任务算力开销，难以评估其在真实控制闭环中的实时性。

- **RMBench 失败率极高**：四个记忆依赖任务平均成功率仅 12.5%，绝对性能很低，说明该方法对长期记忆依赖任务的帮助仍然有限，相关结论需要谨慎看待；同时该 benchmark 任务数量过少，难以支撑稳定性判断。
- **缺少失败模式与细粒度分析**：论文主要报告终端成功率，未对规划错误、执行失败、验证失败、恢复失败等来源进行分解，无法定位运行时各阶段的具体贡献或剩余瓶颈。
- **任务特定微调与通用性存在矛盾**：RoboTwin 2.0 上每个任务独立微调 π0.5 策略，性能提升可能主要来自低层策略的任务专门化，而不是 EmbodiedSkills 执行接口本身的增益；这削弱了“通用智能体层”结论的可迁移性。
- **运行时规则构建成本未量化**：技能契约、先决条件、后置条件和失败映射可能依赖任务特定的人工定义或额外标注，扩展到开放世界任务时的可扩展性、维护成本和自动化程度尚不清楚。
- **未涉及真实机器人评估**：实验均在模拟或离线基准上进行，未验证执行时延、物理接触可靠性、传感器噪声和真实本体差异对运行时守卫和验证器的影响。
- **高层监督数据需求不透明**：调度器使用部署一致的决策轨迹进行监督，可选闭环优化还需要额外交互数据；论文未报告这些数据的规模、标注成本或数据效率，影响可复现性和实用性评估。

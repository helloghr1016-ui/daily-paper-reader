Abstract 

Long-horizon manipulation requires robots to translate task intent into physical interactions as the scene changes. Vision-language models (VLMs) offer semantic and spatial reasoning, while visuomotor policies provide fine-grained control. Yet ambiguous goals and dependencies between actions make their integration challenging. We introduce Atomic Policy, a framework that composes learned ma-nipulation skills through grounded steering and execution feedback. A VLM estimates the symbolic state and goal, and a PDDL solver constructs a skill plan. An agentic harness steers each skill through language, visual point-ing, or both, and verifies its outcome to guide phase tran-sitions and replanning. A common phase-level interface supports specialized policies and generalist action models. Experiments in simulation and on a real robot show how Atomic Policy improves task following and supports recov-ery in complex, long-horizon manipulation. Project page:

1. Introduction 

Long-horizon manipulation requires a robot to pursue its task goal while reasoning about a scene that changes with every interaction. Instructions may leave intermediate steps implicit, and an unsuccessful action can alter what is fea-sible next. Vision-language models (VLMs) provide a ba-sis for this reasoning, enabling robotic agents to interpret instructions and coordinate perception, planning, and con-trol [7, 18, 23]. Perceptual and geometric tools help these agents resolve spatial relationships and ground ambiguous 1arXiv:2611.32813v1 [cs.RO] 24 Nov 2026 or underspecified instructions in the scene [8]. Visual feed-back then allows them to monitor progress and revise deci-sions as execution unfolds [7, 20]. Translating these decisions into reliable manipulation re-mains difficult. The physical interactions available to an agent are constrained by its execution interface [18, 61]: identifying the correct object and operation does not spec-ify the motion needed to complete the interaction. Analytic primitives can struggle with complex grasps, constrained placement, and articulated-object interaction [66]. Imitation learning provides fine-grained motor behaviors learned from demonstrations [10, 67]. Vision-language-action models (VLAs) extend this capability to language-conditioned control, demonstrating semantic generalization and extended task execution in unfamiliar settings [20, 46]. Reliable execution nevertheless remains challenging when a familiar behavior must be redirected toward a different tar-get or composed with other skills in a new sequence [7, 66]. Recent efforts address skill reuse and coordination through procedural knowledge and code-based skills [24, 36], orchestration of learned motor policies [7, 32, 65, 66], and skill transitions guided by world models [64]. We fo-cus on how task reasoning can steer these motor behaviors while remaining responsive to their outcomes. The agent must specify the intended interaction and its target, then de-termine whether the resulting state supports the next step. Grounded steering and verification therefore become part of skill composition. We introduce Atomic Policy (Fig. 1), a framework that separates local manipulation skills from task-level reason-ing and composition. Each atomic skill is a reusable behavior with a phase-level completion condition, imple-mented by either a dedicated visuomotor policy or a shared language-conditioned model. A VLM-based agentic har-ness estimates the symbolic state and goal, and a PDDL solver composes the skills according to their preconditions and effects. The harness steers each phase through lan-guage, visual pointing, or both: language specifies the in-teraction and its referents, while points make spatial targets explicit. A VLM checker verifies the outcome and deter-mines whether to continue, advance, or replan from the cur-rent scene. This common interface allows task reasoning to redirect and compose skills while learned policies generate local motion, supporting recovery as execution unfolds. Our contributions are threefold. (1) We introduce Atomic Policy, a framework for com-plex, long-horizon manipulation that connects task-level reasoning to learned skill execution through grounded steer-ing and verification. (2) We formulate point and language steering as comple-mentary interfaces for skill composition. A common phase-level abstraction supports specialized visuomotor policies and generalist action models within the same planning and execution loop. (3) We evaluate the framework in simulation and on a real robot across tasks requiring dependent skill sequences and interpretation of ambiguous or underspecified goals. Comparisons, ablations, and failure analysis examine how steering and replanning contribute to task following and re-covery. 

2. Related Work 

Agentic Robotics. Frontier multimodal models provide reasoning and tool-use capabilities [12]. Robot agents use these capabilities to call learned policies as tools [7, 32, 65] or generate executable robot programs [18, 51, 55]. Har-ness VLA [66] combines a frozen VLA contact primitive with analytic actions. Other systems co-design physical tools and action plans [19] or learn to use tools for spa-tial reasoning [8]. Agents also acquire reusable skills or refine programs through practice [6, 24, 36, 61], and im-prove policies or execution through real-world trials [54]. Agent-generated demonstrations and program annotations also support policy learning [35, 50]. Benchmarks test au-tomation [56], manipulation for evidence gathering [3], and memory [53]. Plans can also be evaluated using world and video models [17, 64]. Neuro-symbolic representations fur-ther structure task reasoning [37]. VLMs support task plan-ning [26] and can be coupled with PDDL-based or task-and-motion planning [39, 58, 63]. PLanAR [23] uses sym-bolic action schemas for verification and replanning, with grasp-pose generation and parameterized primitives for ex-ecution. Other work learns composable skills from unseg-mented demonstrations [42, 49] or composes short-horizon plan distributions through search [40]. VLM-based systems also support visual failure detection and execution moni-toring [16, 69]. Atomic Policy formulates skill execution through a common phase interface, coupling the selected behavior and target to a completion condition. This sup-ports dedicated policies and shared action models within symbolic planning and verification. 

Generalist Policies and Grounding Interfaces. Imita-tion learning acquires visuomotor skills from demonstra-tions [10, 67]. Generalist policies scale imitation learn-ing to large robot datasets [5, 30, 45]. Vision-language-action models support language-conditioned robot con-trol [21, 43, 46, 62]. Simulation training enables zero-shot transfer to real robots [15, 57], while RoboArena evaluates generalist policies across institutions [1]. When conditioned only on a full-task prompt, a policy must infer the current subtask and target during execution. Intermediate reason-ing takes the form of language motions [2], embodied rea-soning steps [60], or subtask instructions from a high-level model [20, 52]. 3. Method 

Atomic Policy composes learned manipulation behaviors through a phase-level interface that specifies the active skill, its target, and the evidence required for completion. A ded-icated policy or shared action model executes each phase, steered by language instructions, image points, or both. The harness grounds task intent, composes phases, and uses vi-sual feedback to continue, advance, or replan. Figure 2 illustrates the framework through a drawer-manipulation task.

The policy generates local motion through repeated queries from the latest ob-servations until the checker advances the phase or requests replanning. A VLM checker periodically evaluates the current phase against a task-specific checklist using visual observations and robot state. It returns not_done to continue execu-tion, done to advance to the next phase, or replan when the remaining plan needs revision. For example, advanc-ing from pick to place requires visual evidence that the blue cube is grasped and lifted (Fig. 2). On replan or a phase timeout, the planner re-estimates the symbolic state and solves from the latest observation. If the drawer is al-ready open, the new plan can skip the opening sequence and proceed with the remaining phases. Execution resumes from the current observation with updated steering inputs, closing the planning and verification loop. The planner, grounder, and checker require no training on task-specific robot demonstrations. Implementation details and execu-tion pseudocode are provided in Sec. A. 

3.2. Point Grounding and Steering 

Point steering makes the spatial target of a skill explicit. For each target-dependent phase, the harness turns gk

into a pointing query, such as “Point to the blue cube”. MolmoPoint-8B [11] grounds this query in the current primary-camera image and returns a 2D point pk ∈ [0 , 1] 2

in normalized image coordinates. The point is refreshed during execution so that the policy can follow changes in the target’s image location. In the drawer example, grounding identifies the handle for grasp , the blue cube for pick , and the drawer as the des-tination for place , providing the spatial reference needed for each interaction. The selected policy receives uk = pk along with its vi-sual and proprioceptive observations. Skill selection speci-fies the behavior, and the point identifies its target; the pol-icy determines the approach and interaction from its obser-vations. This lets the harness resolve semantic intent and direct a skill toward a named target without passing the full task instruction to that skill. For phases without a sepa-rate target, the point input is omitted. Our specialized skill bank learns these behaviors from phase-segmented demon-strations; its architecture and training details are given in Sec. A.3. 

3.3. Language Grounding and Steering 

For language steering, the harness expresses the selected skill and its resolved target as a short phase instruction. We use phase-specific templates; for example, “grasp the {ob-ject} and lift it” becomes “grasp the blue cube and lift it”. The resulting phase instruction ℓk provides the steering in-put uk = ℓk to a language-conditioned policy. The harness specifies the immediate operation and its referent, while the policy localizes the named target in its observations and generates the motion. Phase transitions and replanning fol-low the same verification loop as point steering. Vision-language-action models provide a natural imple-mentation of this interface because they already map lan-guage, images, and robot state to actions. A shared model can therefore execute different atomic skills through phase-specific prompts. We instantiate language steering with 

π0.5, using phase prompts without points because its native interface does not support point conditioning. Existing policies also support combined steering: Mol-moBot [15] accepts language and point inputs, while GR00T 2 [44] uses language instructions with visual grasp and release markers. 

4. Experiments 

We evaluate Atomic Policy on three simulated suites spanning 2D pushing, Franka drawer manipulation, and generalist-policy pick-and-place, followed by real-robot tasks. The tasks combine semantic and spatial ambiguity with dependent skill sequences, allowing us to study how steering and replanning support long-horizon execution. All tasks use the same framework with task-specific phases, PDDL domains, and checker prompts. Section B summa-rizes the simulated suites, and Fig. 3 illustrates phase exe-cution and replanning in simulation and on the real robot.

4.2. Generalist Policies on MolmoSpaces 

PnP Next-To in the MolmoSpaces [31] benchmark requires a Franka arm to pick up a named object and place it next to a named receptacle across diverse household scenes, includ-ing kitchens, dining areas, and living spaces (Fig. 3, third row). Following the benchmark protocol, an episode suc-ceeds if the moved object is placed within 5 cm of the target object, and each episode is limited to 40 seconds. The di-verse scenes require the robot to ground object referents and spatial relations before composing the manipulation phases. Among the simulation tasks reported in MolmoBot [15], PnP Next-To is the most challenging, with its best variant reaching only 28.3% oracle success and 22.6% final suc-cess. We fine-tune MolmoBot [15] on phase-labeled MolmoBot-Data and evaluate on MolmoSpaces-Bench; Sec. B.1 specifies the dataset and bench-mark configurations. The planner and checker use 

gemini-3.8-flash . We evaluate four configurations based on the same MolmoBot backbone. The released DROID [29] checkpoint serves as the zero-shot baseline. The fine-tuned baselines use either the task prompt alone (FT) or the task prompt with one <points> tag for the pickup object and one for the receptacle, both fixed at the first frame (FT + Point). The Atomic Policy configuration uses phase prompts, per-phase points, and the VLM planning and checking loop (FT + Point + Atomic Policy). We also evaluate π0.5 zero-shot and with task-specific fine-tuning. Fine-tuned checkpoints share 20 fixed bench-mark episodes and evaluation seeds across methods. Both zero-shot models share 200 fixed benchmark episodes. At 16k fine-tuning steps, Atomic Policy reaches 48.5% moving-average success, compared with 43.5% for Mol-moBot FT, 27.5% for FT + Point, and 37.0% for zero-shot MolmoBot (Tab. 2; learning curves in Sec. D.1). These re-sults use 200 rollouts per configuration; Atomic Policy also outperforms MolmoBot FT at every reported training step. By comparison, π0.5 achieves 3.0% zero-shot success; its fine-tuned variant reaches 7.5% at 16k steps, with a peak moving average of 8.0%. With both prompt points fixed throughout the task, FT + Point must infer the active target, whereas Atomic Policy specifies it for each phase and fin-ishes 21.0 percentage points higher at 16k steps. The con-trast with static point prompts suggests that spatial guid-ance benefits from being aligned with the active phase. This comparison evaluates the combined effect of phase-specific 6guidance, planning, and checking on the same backbone. 

4.3. Ablation of Points and Replanning 

We ablate replanning and point conditioning in the CLIP-based Atomic Policy (Sec. 4.1). Without replanning, the checker still advances phases but cannot invoke the planner for recovery. Without points, phase policies receive only images and proprioception. Tabletop retains phase selec-tion by the planner and checker, isolating spatial guidance within each phase. Push 5 Blocks instead uses one policy throughout, without planning or checking; its comparison therefore also changes the execution loop. Without point conditioning (Tab. 3), success falls to 0.0% on Push 5 Blocks and 4.4% on Tabletop. On Table-top, spatial guidance improves execution even when high-level phase selection is retained. Replanning has a larger effect on Tabletop, where phases are strongly dependent. A failed grasp or a partially opened drawer can leave later phases in an unsuitable state, and success falls from 64.0% to 17.8% without replanning. The phases in Push 5 Blocks are more independent, and the variant without replanning retains 64.4% success, about 14 percentage points below the full Atomic Policy result of 78.7%. Together, the Table-top ablations show why phase selection alone is insufficient: a skill still needs its intended target, and the remaining se-quence must reflect the state actually reached. Grounding and replanning address these complementary requirements. 

4.4. Real-Robot Experiments 

We evaluate three real-robot tasks (Fig. 3). In Multi-drawer, the robot searches two drawers for a chicken leg and places it in a bin. If the checker finds no target in the first drawer, it triggers replanning to search the other. Stacking requires identifying and stacking colored cubes in the bottom-to-top order specified by the prompt. If a cube falls, subsequent placements may no longer be valid, so the system must de-tect the failure and revise the plan from the observed state. Crossword requires reading the word on a whiteboard and placing letter blocks into numbered slots in the correct or-der. The target word is specified visually rather than named in the prompt, requiring the planner to infer the letter se-quence from the observation. Together, these tasks couple ambiguous or underspecified goals with dependent manip-ulation phases, testing whether scene interpretation and ex-ecution feedback sustain progress over long horizons. We use a Franka Panda robot with a Franka HAND gripper and external and wrist cameras. Hardware and demonstration-collection details are provided in Sec. B.2. We instantiate Atomic Policy with three policy back-bones. DP uses a separate point-conditioned diffusion pol-icy for each phase; MolmoBot receives phase prompts and point coordinates; and π0.5 receives phase prompts with-out point conditioning. The end-to-end baselines fine-tune MolmoBot and π0.5 on whole demonstrations with task in-structions, without phase decomposition or point inputs. Training epochs and optimization steps are matched, and all methods use their final checkpoints. The planner and checker use gpt-6-astra , and MolmoPoint provides spatial grounding. The checker is queried every 128 control steps, and a phase exceeding 256 steps triggers replanning. Each method is evaluated on 20 trials per task (10 in-distribution and 10 out-of-distribution). OOD conditions change cube colors, retrieval objects, and the word or visual cues used for Crossword; Sec. B.2 records the evaluation conditions. Task score measures the fraction of correctly completed grasp/place steps, and success requires a score of 1. We report task scores as percentages with sample stan-dard deviations across trials. Table 4 summarizes the results; Sec. D.2 visualizes indi-vidual trials. Under ID conditions, fine-tuned π0.5 matches Atomic + π0.5 on Multi-drawer and Stacking, but both baselines fall behind on Crossword. Under OOD Cross-word conditions, their rollouts frequently follow the demon-strated word or an incorrect letter sequence rather than the requested target. The real-robot results expose a gap between executing learned motions and adapting them to a changed goal. On OOD Crossword, both end-to-end baselines obtain zero task score, while Atomic + MolmoBot and Atomic + π0.5

reach 72.5 and 60.0, respectively. Thus, the same pol-icy backbones become more responsive to the requested goal when guided through explicit phases. The improve-ment with Atomic + π0.5, which receives no points, shows that language-based phase guidance and closed-loop execu-tion alone can recover substantial performance. Atomic + MolmoBot combines this guidance with spatial targets; the matched-backbone comparisons are detailed in Sec. D.2. The failure analysis reveals a corresponding shift in what limits performance. On Crossword, incorrect objects, or-der, or placement locations account for 36 of 39 unsuccess-ful baseline trials, whereas grasp and place errors account for 25 of 31 unsuccessful Atomic Policy trials (Sec. D.3). Explicit phase guidance therefore reduces failures in select-ing and sequencing actions, leaving physical execution as the dominant source of remaining errors. This distinction also explains why stronger task steering does not guaran-tee success on every task: Atomic + DP performs well on Crossword but struggles with the precise block alignment required for Stacking. High-level guidance can specify and retry the correct action, but its completion still depends on the precision of the low-level policy.

On Crossword, fine-tuned generalist policies often reproduce the demonstrated word or follow an incorrect sequence when the visual goal changes. Atomic Policy improves task progress, while its remaining failures predominantly involve grasping and placement (Secs. D.3 and 4.4). The generalist-policy comparisons assess the combined effect of phase-conditioned training, steering, and execution feed-back. Several limitations remain. The phase set, PDDL do-main, and checker prompts are specified manually for each task family, and demonstrations require phase and point annotations. Execution depends on the accuracy of the VLM and pointing model, whose inference also adds la-tency. Zero-shot gpt-6-astra outputs end-effector dis-placements from camera images (Sec. C.2). Direct control reaches 98.0% success on Push 5 Blocks, compared with 86.3% for Atomic Policy, whereas Atomic Policy reaches 60.0% success and a score of 80.0 on Tabletop, compared with 52.0% and 69.5. Learned skills thus matter most for contact-rich phases that require precise and timely control, while planar pushing from a static view is within reach of direct VLM control. Future work includes automatic phase discovery and runtime selection between direct VLM con-trol and learned skills. 

6. Conclusion 

We presented Atomic Policy, connecting symbolic planning to learned skills through a shared steering and verification interface. Phase-specific language and 2D image points support both specialized policies and shared action mod-els. Experiments in 2D pushing, tabletop manipulation, and pick-and-place demonstrate the benefits of explicit steer-ing and feedback. A. Method Implementation Details 

The following implementation details instantiate the com-mon execution loop introduced in Sec. 3. 

A.1. Planning and Execution 

Each PDDL operator specifies an atomic phase through its preconditions and effects. For the drawer task, the opera-tors are grasp-handle , open-drawer , pick-cube ,

place-in-drawer , and close-drawer ; the pushing task uses a single push-to-slot operator. The VLM re-turns the current ground predicates and task goal in a fixed format. A breadth-first search over ground states returns the shortest operator sequence to the goal. The domains have at most five operators, and the solver enforces their preconditions and effects during search. Replanning repeats state estimation and search from the current observation, so already-satisfied goals need not be executed again. Every C control steps, the checker receives the phase de-scription together with the current primary-camera frame, wrist-camera frame, and gripper opening. The prompt lists the visual evidence required for successful completion of each phase. The checker returns done , not_done , or 

replan , together with a one-sentence justification. Aphase timeout after T steps also triggers replanning. Al-gorithm 1 gives the point-steered instantiation of this loop; for phases with gk = ∅, grounding and point conditioning are omitted. The no-replanning ablation in Sec. 4.3 retains checker-controlled phase transitions but disables plan revi-sion. Push 5 Blocks is the exception. Instead of the full frame, the checker receives a crop centered on the current target and judges whether the target is fully covered by the in-structed block. A.4. Wrist-Camera Pointing 

Real-robot point-conditioned policies also receive a target point in the moving wrist-camera view. Unlike the fixed primary-camera point, this point must be updated as the end effector moves. Image-based tracking proved unreliable: SAM 2 drifted to similar cubes or gripper fingers and could not consistently isolate individual Crossword tiles. We in-stead maintain a 3D target xk in the robot base frame and project it into the wrist image:

A geometric visibility flag νt indicates whether the target is in front of the camera and within the image. Annotation, training, and deployment use the same geometry. We estimate the wrist-camera intrinsics and Ecam di-rectly from demonstrations, without a calibration target. For each grasp, we approximate the cube’s 3D position by the fingertip center at gripper closure and obtain 2D correspon-dences by tracking the cube backward through preceding wrist frames with SAM 2 [48]. Minimizing reprojection error gives a median error of 8.0 pixels on the 672 ×376 im-age. The unchanged camera mount allows this calibration to be shared across all three tasks. We then infer 3D targets from gripper events and fingertip poses, sharing each target between its approach and contact phases. Projecting these targets with Eq. (3) provides per-frame wrist points without manual frame-by-frame annotation. For Atomic + DP, the two-dimensional point input to 

ψ in Eq. (2) is replaced by the five-dimensional vec-tor [ pk, w t, ν t ], which concatenates the primary-camera point, the wrist point normalized to the wrist-image crop, and the visibility flag. The primary-camera point remains fixed within each phase, while the wrist point uses the most recent observation. When νt = 0 , the wrist point is set to zero. During training, we add Gaussian noise with a stan-dard deviation of 0.02 to visible wrist coordinates and mask the wrist point and visibility flag with probability 0.15. Atomic + MolmoBot receives the visible wrist point as an additional <points> tag on the current wrist image. During deployment, MolmoPoint-8B is queried on the wrist image at the start of each target-dependent phase, during the pause for primary-camera grounding. The pre-dicted pixel is back-projected onto a plane at the phase’s target height, estimated from median contact heights in the demonstrations and adjusted for stack level during place-ment. This intersection initializes xk. We then update wt

at every control step using Eq. (3), without image process-ing, including during target occlusion. Asynchronous wrist queries refine the estimate every 16 control steps, or every 8 steps until two consistent predictions confirm the target. Each prediction is back-projected using the robot pose at image capture; predictions on gripper fingers, identified by a SAM 2 mask, are rejected. At each policy query, the up-dated wrist point and visibility flag are supplied using the same encoding and masking rules as in training. 

A.5. Real-Robot Policy Training 

All policies are trained separately for each task on the demonstrations described in Sec. B.2, and each method uses the same training budget across the three tasks. For Atomic + DP, each phase policy uses the architecture of Sec. A.3 and is trained for 500 epochs with a batch size of 256 and a cosine learning-rate schedule. For Atomic + MolmoBot, we initialize from MolmoBot-DROID, train the action expert for 8,000 steps with the language model frozen, and use a batch size of 64. For Atomic + π0.5, we fully fine-tune π0.5-DROID in joint-position space for 20,000 steps with a batch size of 32 and 15-step action chunks at 15 Hz. The fine-tuned MolmoBot and π0.5 baselines follow the same recipes and training budgets as their Atomic Policy counterparts, with whole-task instructions in place of phase prompts and points. We set these budgets from pilot runs on a separate sorting task, where they offered a good balance between training time and policy performance. For every method and task, we deploy the final checkpoint and use it for all 20 evaluation trials without further checkpoint selection.
